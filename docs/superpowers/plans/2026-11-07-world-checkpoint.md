# 世界正本と軍事の一括保存・復元

## 根拠と制約
監督の2026-11-07指示6項目。単一エージェント、codex/politics-military-p0。承認済みP3aから継続。世界共通ID・既存のpeopleSave/peopleLoad・経済/集落/民族/建築の正本を維持。政治軍事だけを最終セーブ正本にしない。現行HTMLのapplyStateはグローバルを書き換えるため候補復元には呼ばない。

## Task 1 一括検証ゲート
- src/persistence/world-checkpoint.mjs：世界担当が登録するsave/restore参加部品の依存順に候補を構築し、全体検証後に単一のactive参照だけ交換する。構成ごとの保存バージョン、共通checkpointId/dayを検証。未知/欠落部品・混在保存・例外・非同期・循環依存を拒否する。保存時も入力/正本を共有せずtyped arraysを保持する。
- src/politics-military/military-checkpoint.mjs：世界所有のpeople/units/配送/実行正本へ接続するID参照部品。各正本を再生成しない。発信/配属/命令を同じ候補peopleへ再接続する。
- tests/persistence/world-checkpoint.test.mjs：実Population、実peopleSave/Load、実配属/命令を用いる。配送途中/食料移転後/命令結果受領前の保存を用意し、二重効果・不正部品の部分適用・世界ID/時計/参照不一致・保存入力変更を検査する。別世界部品は拒否。世界部品に建築・民族・集落・未知の既存拡張を含め保持する。
- 初期ゲートをRED→GREENし、この時点の整合性試験が通ってからTask 2へ。

## Task 2 伝令・実在庫への最小接続
- src/transport/courier-state.mjs：既存人物IDの位置と伝令任務を世界の交通状態として扱う任意利用部品。既存geography.routeを再利用。実在する伝令1人に複数の同時任務を割り当てない。移動は明示されたtravelHoursで経路上を進む。速度・勤務時間/日・時間倍率は新規確定しない。到達は実際の座標一致で判定。途中のleg進捗/位置/任務/進行操作IDを保存し再送に備える。受信者が離れた場合は到達にしない。
- src/economy/food-transfer.mjs：既存g.food総量とfresh/dried内訳から、同じ場所にいる実人物の世界交通側cargoへ実移転する。輸送後の荷下ろしも同じAPI。権限と容量の明示確認。kgは既存食料単位。既存の総量と内訳を重複集計しない。輸送中の食料は集落在庫から除く。operationIdを世界経済の取引結果と同時に記録し、再送・ロードで再減算しない。
- 不明位置・経路遮断・死人・権限不足・容量不足は無変更。既存物資を軍事用に複製しない。補給消費・腐敗・軍務の労働配分や世界全体の時計接続は未実装として明示する。
- 実装した部品を世界所有の保存参加部品へ登録する結合試験。配送途中からの再開、在庫移転直後の中断、同一人物/同一輸送の二重計上を検証。

## Task 3 検証・成果
- 全testsのNode検査、差分チェック、著者自己レビュー。小単位コミット。main/公開HTMLを変更しない。
- 世界担当向けに一括保存の呼出契約、旧セーブ移行の境界、未接続のUI/全世界スキーマ/原子ストレージ取引を明記。公開は前回と同様ローカル成果を先に用意する。

## 世界側への委譲
全世界スキーマの最終決定、旧データ移行、IndexedDBにおける一回の原子的書込、全グローバル参照の切替は世界担当の正本。今回のコーディネーターはその検証ゲートであって独立した政治ゲームのセーブではない。登録部品のsave/restore/validateは同期かつactive正本に副作用を起こさない契約。任意の悪意あるコールバックの副作用までロールバックする機能ではない。
