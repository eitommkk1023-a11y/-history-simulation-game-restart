# World of History: 実寸座標・地形問い合わせ（第1段階）

## 合意済みの方向と今回の範囲
既存生成器を維持し、乾いた平地・丘陵で実寸の三人称を検証する。その前提となる座標変換と読取専用の地形問い合わせだけを今回追加する。
単一エージェント。main直接変更・マージ・配信なし。既存Seed、HTML、保存形式、交通アダプターは変更しない。

## 方針
既存HTMLへの直接追加は影響範囲が広いため採らず、依存ライブラリなしの独立ESモジュールにする。
過去のチャンク試作はセル中心を使うが、旧表示との接続がないため無条件には流用しない。
今回の実装判断として、標高配列の添字を格子点として扱う。

- 共通座標: 北西端を原点、xMが東、yMが南、標高はm。Three.jsのYは標高、Zは南。
- 格子点(i,j)は(i*s,j*s)。sはworld.geology.kmPerBlock*1000（既存版3330m）。半セルの加算はしない。
- 標高点間の範囲は(width-1)*s × (height-1)*s。最後の格子点も範囲内。
- 広域表示との変換は旧toWorldX/toWorldZの式をそのまま使用。広域の高さ強調とは分離する。
- 局所座標は原点との差を返し、世界位置を変更しない。
- 標高は双線形補間。勾配・法線はその補間面の解析的な微分。端では最後の区間からの片側微分を使う。
- 陸海・水域・植生・湖IDは最寄りの格子点から取得。補間した実際の海岸線や歩行可否を意味しない。
- 海面は0m、湖は既存lakeLevelsを参照。川の水位や不明な湖面はnullとして返し、推測しない。
- 配列はコピーせず、その後の標高変更も読み取る。新しい世界オブジェクトができた場合はアダプターを作り直す。

## 今回含めないもの
詳細ノイズ、チャンク、LOD、コライダー、プレイヤー、UI、セーブ項目追加。
sampleBaseの標高は基礎地形の値であり、将来の描画三角形と一致する接地問い合わせではない。接地用の関数は次段階で表示メッシュと合わせて追加する。

## 合格条件
旧広域表示と格子点の対応・往復変換、端点、非正方形の世界、実寸の傾斜、湖底と湖面の分離、元データ非変更、入力検査を確認。
既存交通テストも通す。HTMLのGit blob SHAが基準版と同じことを確認する。
