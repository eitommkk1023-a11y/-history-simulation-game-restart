## 2. つなぎ方の案
1. **環境アダプタ（新規、独立）** `src/ship/world-environment.mjs`
   `world` を受け取り、船が使う形 `{ wind(x,y,t), current(x,y,t), depth(x,y,t), seabed }` を返す。座標はメートル。既存の `geography-adapter.mjs` と同じ作り（読み取り専用、固定データでテスト）。
   - `wind`：`clock.day` の月と粗い格子から、向きと速さを引いて風ベクトルにする。月の境は補間する。
   - `current`：`currentU/V` を÷100。
   - `depth`：`-elev`（海のみ。陸は0）。1ブロックは約3.33kmなので、船の大きさ（数十m）に対して粗すぎる。ブロック間の補間と、地形の詳細化（Seed固定）との整合が必要。
   - `seabed`：データがないので、当面は一定値（砂）。
2. **船の管理（新規）** 船ID・状態（位置は世界座標のメートル）の一覧、近距離だけ毎フレーム更新、遠距離は集約。保存は `serializeState` に `ships` を足す。
3. **3D表示（新規）** 断面データから船体メッシュを作り、本体の場面へ追加。
4. **本体への取り込み**：`tools/build-ship-viewer.mjs` と同じ方式で、船のコードを1つにまとめて本体の `<script>` に入れる。

# 実装済み：環境アダプタ `src/ship/world-environment.mjs`
検証：`tests/ship-world-environment.test.mjs`（8件）

## 使い方
```js
import { createWorldEnvironment } from './src/ship/index.mjs';
const env = createWorldEnvironment(window.__geo.world, {
  origin: { x: 1200, y: 800 },          // 船の座標(0,0)に当たるブロック座標
  dayAt: (t) => window.__geo.clock.day, // 船の時刻t(秒)に対応するゲーム日。時間の橋渡しは未決定
});
vessel.step(0.1, env);                  // env は {wind, current, depth, seabed} をそのまま渡せる
```
- 船の座標はメートル（X=東、Y=北）。`toBlock` / `toShip` でブロック座標と相互変換。南北の反転（`Y = -y`）はここだけで行う。
- 風：月ごとの平均値を、月の中ごろを基準にして隣の月と補間し、格子の4点で双一次補間する。突風はない。
- 海流：`currentU/V`（×100、m/s）。陸ブロックでは0。
- 水深：`-elev`（海のみ）。4ブロックの双一次補間。陸は0。範囲外は端の値。
- 海底の種類：固定値（既定は砂）か関数を渡す。

## 実際の世界データでの確認（2026-11-04、Seed 12345、ヘッドレスのChromiumで生成）
- 生成は約32秒。`world.elev` はFloat32（−9655〜6088 m）、`world.type` はUint8。海は約55%。前提どおり、海の標高は負。
- 気候の格子は `gridStep=8`、375×375。`windDir/windSpeed` は12か月分、`currentU/V` は1枚。海流の最大は約1.2 m/s、風の最大は約14.5 m/s。単位の仮定（÷100、÷10）は妥当。
- 海のセル(141,50)で、アダプタの出力が配列から手計算した値と一致（風、海流とも）。風向の符号（来る向き→吹く向き）も確認。水深は双一次補間のため元の標高と少しずれる（2298 m → 2261 m）。
- 1回の問い合わせは約1.2マイクロ秒。負荷の問題はない。
- 海流の向き（u=東、v=北）は、風との整合は確認したが、海流の生成コード自体での確認は未実施。

## 制約
1. 水深・風・海流の細かさは1ブロック（約3.33km）／気候の1セル（8ブロック＝約27km）。岸や浅瀬は解像できない。座礁などは、近距離の地形の詳細化（Seed固定）とつなぐまで、実際の海岸の形とは一致しない。
2. 潮汐・波・海底の種類のデータは本体にない。
3. 時間の橋渡し（`dayAt`）、船の置き場所（`origin`）の決め方は未決定。
4. 本体のHTMLへはまだ取り込んでいない。

1. **本体の保存データには入っていない。** 船は別の保存先を使う。本体の保存（`serializeState`／`loadState`）へ入れるには、本体のコードの書き換えが必要（`ships: ...` を足す1か所と読み込み側）。今は書き換えていない。
2. 遠方の船は、近づくまで同じ計算を粗い刻みで続けるだけ。休止中の航海の「追いつき計算」はない。
3. 乗船中のプレイヤーの移動（甲板上の歩行）は、船と一緒に動かしているだけで、船の揺れや甲板の当たり判定はない。

5. 海底の種類・潮汐・波は本体にデータがなく、砂・潮なし・波なしの仮定。
6. 水深は本体の地形の標高から取る。岸の近くの細かい形は地形の詳細化に依存する。

## 船UI v2(開発者モード専用・本作HUDに合わせた再設計)
- **置き場所**: 船のボタン・一覧・乗員・性能測定は、本作のメニュー(右上「メニュー」)の右端に追加した「船(開発者)」タブの中の「⛵ 船システム」に入れた(旧版の左端開発者枠`#developerPane`しか無いゲームではそちらに入る)。開発者モード(`body.woh-dev`)でないと、船のUIは一切出ない(開発者モードを切ると乗っていれば自動で降りる)。通常画面に常時ボタンは出さない。
- **船に乗っている間の画面**(画面の端だけを使い、中央は空ける):
  - 上端(方位帯の下):計器カード。羅針盤(船首方位、風の来る向き=橙、目標方位=青)、速度・風力・波高・気圧・視程・水深。警告チップ(嵐・予兆・浅瀬・座礁・走錨・航海中の残り)は色分け。
  - 下端(ホットバーの上、ジョイスティックと操作ボタンの間):操作バー。タブで「舵(左/右)・帆(自動/固定、櫂)・錨・航海(目的地、前方3km、中止、時間倍率)」。「降りる」は常に右端。
  - 👁で全部の船UIを隠せる(隠すと👁だけ残る)。
- **配置**: 本作のHUD要素(目標パネル・方位帯・ボタン列・ミニマップ・ホットバー・操作ボタン)の位置を実測して避ける。3つの画面サイズ(844×390、740×340、1180×820)で、タブ全種と隠した状態の重なりを座標で確認済み。
- 直した不具合: 船UIの表示/非表示を切り替える関数が、以前の修正で抜け落ちていた(👁が効かなかった)。新UIで定義し直した。
- サンドボックス(単体ページ)のUIは従来のまま。
- 計器カードは、ボタン列の下・ミニマップのズームボタンの左の空きに小さく置く(羅針盤・速度・風・最優先の警告1つ)。タップで全計器(波・気圧・視程・水深・全警告)に展開し、もう一度タップで戻る。👁はその左。
