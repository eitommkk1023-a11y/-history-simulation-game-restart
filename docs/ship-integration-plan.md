# 船舶システム：本体への接続計画（調査結果）

調査対象：`World-of-History-v30-development.html`（本体）と `自然地理生成器.html`。生成器部分は両ファイルでほぼ同じ（差分34行）。調べたのは、風・海流・水深・時間・保存・イベントの口だけ。**コードは変更していない。**

## 1. 本体側で見つかったデータ
| 船が必要とするもの | 本体の既存データ | 状態 |
|---|---|---|
| 世界の入口 | `window.__geo`（`world` `seed` `clock` `sim` `serializeState` `loadState` `saveTo` など） | あり |
| 水深 | `world.elev`（3000×3000、m）。陸は `type≠0`、海は `type=0`。海の `elev<0` が水面下の深さと思われる | 要確認（単位と符号） |
| 風 | `world.climate.cell` の `windDir`（月ごと、0〜255＝256分割の角度、「風の来る向き」）と `windSpeed`（×10、m/s）。粗い格子 `gridW×gridH` を `labCell(bx,by)` で引く | あり。ただし月ごとの平均で、突風・日変化はない |
| 海流 | 同じ `cell` の `currentU` `currentV`（×100、m/s） | あり（粗い格子） |
| 日付 | `clock.day`（1年360日、1か月30日） | あり。船の時間刻み（0.1秒）との橋渡しが必要 |
| 保存 | `serializeState()` が1つのオブジェクトを作る（`format` `seed` `clock` `history` `sim` など）。IndexedDBへ保存 | あり。船は未登録 |
| イベント | `postEvent({cat, imp, text})` | あり。分類名は既存に合わせる（要決定） |
| 3D | Three.js r128（`世界生成器` は cdnjs、本体は埋め込み） | あり。場面（scene）の取り方は未調査 |
| 潮汐・波・海底の種類 | **なし** | 未実装 |
| 人物ID・在庫・家計 | **リポジトリにない** | 接続不可（別資料の内容） |

## 2. つなぎ方の案
1. **環境アダプタ（新規、独立）** `src/ship/world-environment.mjs`
   `world` を受け取り、船が使う形 `{ wind(x,y,t), current(x,y,t), depth(x,y,t), seabed }` を返す。座標はメートル。既存の `geography-adapter.mjs` と同じ作り（読み取り専用、固定データでテスト）。
   - `wind`：`clock.day` の月と粗い格子から、向きと速さを引いて風ベクトルにする。月の境は補間する。
   - `current`：`currentU/V` を÷100。
   - `depth`：`-elev`（海のみ。陸は0）。1ブロックは約3.33kmなので、船の大きさ（数十m）に対して粗すぎる。ブロック間の補間と、地形の詳細化（Seed固定）との整合が必要。
   - `seabed`：データがないので、当面は一定値（砂）。
2. **船の管理（新規）** 船ID・状態（位置は世界座標のメートル）の一覧、近距離だけ毎フレーム更新、遠距離は集約。保存は `serializeState` に `ships` を足す。
3. **3D表示（新規）** 断面データから船体メッシュを作り、本体の場面へ追加。
4. **本体への取り込み**：`tools/build-ship-viewer.mjs` と同じ方式で、船のコードを1つにまとめて本体の `<script>` に入れる。

## 3. 先に決める必要があること（未決定）
1. **風向の基準**：生成器の座標（y軸が北か南か）と `windDir` の角度の向きが、船の座標系（Y=北、方位は北から時計回り）と同じか。**要確認。** 逆なら船が逆向きの風を受ける。
2. **1ブロック約3.33kmと、船の大きさのギャップ**：近距離では何メートルの格子で水深を引くか（地形LODの仕様と合わせる）。
3. **時間の橋渡し**：ゲームの1日と、船の物理の時間刻み（0.1秒）の関係。
4. **海底の種類**：地質データから決めるか、別データを作るか。
5. **潮汐・波**：後から足すか。足すなら本体側の生成が必要。
6. **イベントの分類名**、保存形式のバージョン。
7. **人物・荷物・お金**：人口・経済側の実ソースがこのリポジトリにない。船の中の人や荷物のIDを何に結ぶかは、そちらの資料が必要。

## 4. 次にやること（提案）
- 環境アダプタ（上の1）を、既存の地理アダプタと同じ形で作る。固定データでテストできるので、本体を変えずに進められる。**風向の基準（3の1）は仮定のまま作らず、確認できるまで切り替え可能にしておく。**
- そのあと、船の管理、3D表示、本体への取り込みの順。
