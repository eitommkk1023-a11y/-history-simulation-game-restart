## 2. つなぎ方の案
1. **環境アダプタ（新規、独立）** `src/ship/world-environment.mjs`
   `world` を受け取り、船が使う形 `{ wind(x,y,t), current(x,y,t), depth(x,y,t), seabed }` を返す。座標はメートル。既存の `geography-adapter.mjs` と同じ作り（読み取り専用、固定データでテスト）。
   - `wind`：`clock.day` の月と粗い格子から、向きと速さを引いて風ベクトルにする。月の境は補間する。
   - `current`：`currentU/V` を÷100。
   - `depth`：`-elev`（海のみ。陸は0）。1ブロックは約3.33kmなので、船の大きさ（数十m）に対して粗すぎる。ブロック間の補間と、地形の詳細化（Seed固定）との整合が必要。
   - `seabed`：データがないので、当面は一定値（砂）。
2. **船の管理（新規）** 船ID・状態（位置は世界座標のメートル）の一覧、近距離だけ毎フレーム更新、遠距離は集約。保存は `serializeState` に `ships` を足す。
3. **3D表示（新規）** 断面データから船体メッシュを作り、本体の場面へ追加。
4. **本体への取り込み**：`tools/build-ship-viewer.mjs` と同じ方式で、船のコードを1つにまとめて本体の `<script>` に入れる。

## 3. 先に決める必要があること（未決定）
1. ~~**風向の基準**~~ **確認済み（2026-11-04、コードを読んで確認。実行での検証はまだ）**：
   - `windDir` は「風が吹いてくる方位」で、**北=0、時計回り**、256分割（コメントと `clmWindFrom` の計算式 `atan2(-u,-v)` による）。船側の「風の来る方位」と同じ向きなので、そのまま使える。
   - 風ベクトル(u,v)は **u=東、v=北**。
   - 一方、**格子とブロックの y は南向きに増える**（火山灰の風下計算のコメント「格子の y は南向き」）。x は東向き。船の座標（Y=北）へ変換するときは `Y = -y` とする。
   - 海流 `currentU/V` も風と同じ (u=東, v=北) だと思われるが、コードでの確認は風ほど確実ではない（要確認）。
2. **1ブロック約3.33kmと、船の大きさのギャップ**：近距離では何メートルの格子で水深を引くか（地形LODの仕様と合わせる）。
3. **時間の橋渡し**：ゲームの1日と、船の物理の時間刻み（0.1秒）の関係。
4. **海底の種類**：地質データから決めるか、別データを作るか。
5. **潮汐・波**：後から足すか。足すなら本体側の生成が必要。
6. **イベントの分類名**、保存形式のバージョン。
7. **人物・荷物・お金**：人口・経済側の実ソースがこのリポジトリにない。船の中の人や荷物のIDを何に結ぶかは、そちらの資料が必要。
