# 建築システム統合設計 v1 の実装（報告）

設計書：`woh_architecture_materials_integrated_v1.md`。既存の建築・村生成・人口・民族・経済（`arch-gen.js`・`settle-layout.js`・`people-core.js`・`forage.js`・描画）と照合してから実装した。実機の検証は未実施。

## 実装できた機能

### 1. 建築素材6系統と簡易加工（`npc/materials.js`）
- **6系統**：木・石・土・植物・動物由来・金属。素材20種（丸太・棒材・樹皮・割り板・角材／自然石・割石・整形石・石板／粘土・芝土・練り土・日干しレンガ・焼成レンガ・漆喰／茅束・葦・編み材／獣皮・フェルト／金具）。
- **加工6グループ**：切る削る・割る砕く・成形・乾燥・繊維加工・焼成（低温／高温）。金属加工は条件付き。素材ごとに「原料のまま（加工なし）」か「加工の連鎖」を持つ（例：日干しレンガ＝成形→乾燥、焼成レンガ＝成形→乾燥→高温焼成）。
- **使える条件**：資源が手に入る（環境の豊かさ）かつ、必要な建築技法を知っている。資源が無ければ素材は出ない。金属は初期の必須条件にしない。
- **既存名との対応表**：`timber/stone/adobe/mud/turf/reed/brick/hide`、`thatch/shingle/slab/…` は維持し、新素材に対応づけ（1800通りの組み合わせで未対応 0）。既存セーブは読める。
- **部位ごとの素材と必要量**：基礎・骨組み・壁・屋根・床・開口部。必要量は寸法に応じ、系統ごとに集計（二重計上なし）。加工の品質は粗い／標準／精密。

### 2. 部位ごとの耐久・劣化・修理（`settle-layout.js`）
- 部位ごとの健全度（良好／軽度／中度／重度／崩壊）。**固定寿命なし**：素材（腐朽・湿り・摩耗）×品質×気候（湿度・気温・雨・凍結）で、月単位でまとめて劣化。
- **雨漏りの連鎖**：屋根が傷むと、床・骨組み・壁の傷みが速くなる。屋根だけの傷みで建物は消えない。
- **修理**：住んでいる家は手入れされる（屋根・壁・床・開口部を先に。骨組み・基礎は大きく傷んだときだけ）。材料（蓄え）を消費する。材料が無ければ修理できない。屋根を替えても築年は変わらない。修理・取り替えは建物の履歴に残る。
- 骨組み・基礎が傷みきると廃屋（使用不能）、さらに進むと崩壊。空き家は固定年数では消えず、傷み方で決まる（耐久の差で、崩れる家と残る家に分かれる）。
- 開始前の建物は、築年・状態から推定（修繕の履歴も推定として記録）。旧い保存の建物は、最初の更新で素材・状態が補われる（位置・形は変えない）。

### 3. NPCの住居需要と新築・増築・改築
- 家のない世帯は、**空き家・同居・増築・新築・仮小屋**を比べて選ぶ（親族・距離・過密・材料・文化（長い家の技法）で点数が変わる）。新築一択ではない。
- **材料の蓄え**（集落ごと・系統別）は、働ける人手×資源の豊かさで月ごとに増え、新築・増築・修理で減る。足りなければ工事は**待ち（中断）**になり、記録される。待ちが長引くと、簡素な仮小屋を先に建てる。
- **工期**は建物の広さと人手で決まる（固定日数ではない）。着工→建設中（地図・3Dで柱の骨組みだけ表示）→完成→入居。
- **過密**な家は増築を検討する。増築は、他の建物・水・急斜面を避けられなければ失敗（家は変わらない）。同居（1つの建物を複数世帯が使う）に対応。
- NPCの建設要求（`requestBuild`）も同じ仕組みに乗る。古い保存でも需要の仕組みに移行する。

### 4. 村の成長・衰退と建物の歴史保存
- 履歴（`layout.log`）に、着工・完成・同居・増築・増築失敗・工事の待ち・部位の取り替え・空き家・廃屋・崩壊を、日・世帯ID・理由つきで記録。建物ごとの記録（`rec.edits`）に、修理・取り替え・増築・同居・再入居・改築（上限12件）。
- 崩れた建物は重い部品を捨て、位置・用途・履歴だけ残す（保存容量の節約）。
- 保存・再読み込みで、建物の位置・素材・状態・材料の蓄え・工事・履歴が一致（別セッションで確認）。

### 5. 素材・文化による3D外観
- 壁・屋根・基礎の色が、部位ごとの素材と傷みで変わる（新しく直した屋根は明るく、傷んだ壁・屋根はくすむ）。屋根が傷むと穴（雨漏り）が見える。建設中は柱と棟木の骨組みのみ。
- 集落詳細マップ：建物ごとの部位別の素材・傷み（バー）、品質、全体の状態、材料の蓄えと進行中の工事、建設中の建物の表示。

## 未完成の機能
- **金属・動物由来の素材の使われ方**：辞書にはあるが、住居の部位で実際に使われるのは主に木・石・土・植物（動物由来は皮張りの天幕・開口部、金属は一部の集会所の開口部のみ）。
- **加工の工程表示（UI）**：原料→加工品→建材の見込みを一覧する画面は未実装（データ `chainOf` のみ）。
- **部位ごとの品質差**：品質は建物ごとに1つ。部位ごとの違い、乾燥不足などの施工不良は未実装。
- **火災・洪水・戦闘などの出来事による損傷**：入口（部位の健全度を直接減らす）はあるが、出来事側の連動は未実装。
- **土地所有・資金・許可・検査**：工事の材料と人手のみ。資金・土地権利・法制度は未実装。
- **部屋・中庭・複数階**などの内部構造、家具との連動は未着手。
- **遠方の集落の更新**：集落の配置は、プレイヤーが近づいたとき作られ、そのとき経過した月（上限20年）をまとめて進める。遠方で常時進める「集約計算」ではない。20年を超える空白は、残りを省略する。
- 劣化率・材料の生産率・工期・材料の必要量の数値は、すべて仮（実測・バランス検証後に調整）。

## 設計書との違い・注意
- 設計書の「パーツ種類の上限は設けない」は、描画の部品（箱・円柱・屋根）を増やさず、既存の部品の組み合わせで表現した（複雑な形は部品づくりが要るため未着手）。
- 「紀元0年以前は履歴から生成」「以後は需要で新築」の2モードのうち、**以後**は集落が近づかれたとき（または保存後に近づいたとき）に経過月をまとめて計算する。
- 旧仕様（世帯が増えると即座に住居が現れ、空き家は5年で廃屋・12年で撤去）は、設計書に従い廃止した。古いセーブも新しい仕組みで動く。
- 実機（iPhone/iPad）のFPS・メモリ・発熱は未測定。
