# battle-view-v1 報告（野戦の画面表示と、指揮の操作・試作）

小さな野戦の試作（`npc/battle.js`）を、**実際のゲーム画面の上**に出し、地図をタップして命令を出せるようにした。**開発者モードの専用ボタン**から始める（戦争モードの区切りは作らない原則に沿い、通常の画面には出さない。試作の入口にすぎない）。

## 使い方（開発者モードのみ）
- メニュー（≡）に「野戦：敵が攻めてくる／敵が罠を張る／敵は守る」の3ボタン。陸の広い場所（水が少ない）で押すと、周りの1.6km四方に戦場が現れる。あなたは、味方（西・青）の指揮官の位置に立つ。
- 下の操作盤：部隊（A0〜A2・各20人）を選び、命令（持ち場／前進／撤退／伏兵／偽装撤退）を選んで、**地面をタップ**して目標を決める。偽装撤退は、接触する地点、引く先の順に2か所タップ。
- **命令は伝令が運ぶ**：指揮官の位置から部隊へ、黄色い点が走って届く（遅れる、討たれることがある）。届くまで、部隊は前の命令で動く。
- 速度（一時停止・×1・×2・×4・×8）、「視点」（高い所から見下ろす指揮視点）、「中止」。

## 画面の表示
- 兵＝人型の立体（体と頭）。味方は青、敵は赤、倒れた兵は黒っぽく横たわり、逃げる兵は黄色。カメラが遠いほど大きく描く（遠くでも点にならない）。
- 部隊の旗（味方は常に、敵は**見えている部隊だけ**）。選んだ部隊は黄色い輪と、命令の目標の水色の輪。
- **情報は不完全**：自軍が見ていない敵は、描かない。見えた後に倒れた敵は残す。隠れた伏兵も、見つかるまで描かない。
- 状況の行：戦場の経過時間・動ける／倒れた／逃げた・見えている敵・伝令の数・1ステップの計算時間。

## 実装
- `battle.js` を本体HTMLに埋め込み（`<script id="battle-core">`）。場面の組み立ては `battle.js` の `scenario(kind, seed, {field})` に移した（テストと共通）。
- 戦場の地形は、**遊ぶ画面の実際の地形**（標高）から作る。兵の描画は、インスタンス描画（人型2部品＋伝令）。地面の高さは、兵ごとに数フレームに1回ずつ更新。
- 戦場の時間は、現実と同じ速さ（1秒＝1秒、×1の場合）。**ゲームの暦（日付）はまだ連動させていない**（試作）。
- 地面のタップは、地形メッシュへのレイキャスト。戦闘中は住民のタップを無効にし、HUDのホットバーなどを隠す。

## 検証
- Node：test-battle 20件（場面の移し替え後も、統計は同じ：Bの勝ち 0%→63%）。
- Playwright（iPhone横画面、ソフトウェア描画）：戦場の開始（水の多い所は断る）→ 味方60人の描画 → UI → 地面のタップで「前進」→ 伝令が出て届く → 速度×8 → 視点 → 敵が見えた（t=666秒）→ 交戦（t=772秒：味方 倒れた22／敵 12）→ 中止して元の画面へ。エラー0。
- **性能（ソフトウェア描画＝実機より遅い環境）**：計算 1ステップ（0.5秒）あたり 0.4〜1.9ms。1フレームの戦闘処理（計算＋描画の準備）0.1〜1.7ms。描画する兵 60〜120。

## 未確認・限界（正直に）
- **iPhone/iPad の実機は未確認**。ソフトウェア描画での数字で、実機の描画の重さ（GPU）は測れていない。400人規模の描画は未試験（試験は最大120人）。
- カメラは既存の三人称（人物の周りを回る）で、**戦場専用の操作性は未作り込み**（視点の上下左右の動かし方、ズーム、指でのスクロールなど）。指揮視点は固定の高さ。
- 命令は5種類のみ。編隊（陣形）の指定、持ち場の幅・向きの指定、部隊の分割・合流、命令の取消は未実装。
- ゲームの時計（日付・季節・空腹）と戦場の時間が未連動。戦場に入るとゲームの時間は止まらない/動かない（別時計）。
- 負傷・救護・降伏・再集結、敵の指揮官AI（罠を選ぶ・避ける）、任命・兵員割当て、兵站は未実装。
- 戦場の森（被覆）は、描画していない（試作の位置に置いた被覆は計算には効くが、森の絵が無い）。

## 次の候補
1. 実機（iPhone/iPad）で触ってもらい、操作感・描画の重さ・見やすさを確かめる（最優先。気づきをまとめて直す）。
2. 戦場専用のカメラ・編隊の指定・命令の取消など、指揮の操作の作り込み。
3. 敵の指揮官AI、負傷・救護・降伏、森の描画。
