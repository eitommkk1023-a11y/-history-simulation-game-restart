# GPT 設計資料（M5・M6）と現在の実装の照合（2026-11-22）

対象：監督から引き継いだ「M5・M6向けGPT設計資料」と、ブランチ `claude/small-world-v1`（M1〜M4、M5 の入れ物まで）。
凡例：**一致**＝資料どおり／**不足**＝資料にあるが未実装／**矛盾**＝資料と食い違う。重大な仕様変更は、監督の承認が要る。

## 1. 一致している部分
| 資料 | 現在の実装 |
|---|---|
| 初期の8職業（採集・狩・漁・道具・建築・運搬・治療・警備） | `npc-core.js` の JOBS に同じ8つ。農民・牧畜従事者・交易者が別に追加され、農民・牧畜は技術と環境、交易者は舟・車のある港など必要な村に限って現れる（資料の「知識・環境・継続的な需要に応じて成立」と同じ方向） |
| 職業・実際の活動・習得技能を区別する | 人物ごとに職業（`P.job`）と技能11個（`P.skills`）が別。仕事以外の活動（学ぶ・体を鍛える）でも能力が伸びる。技能は、その職に就いている間の実際の活動で伸びる |
| 首長は職業でなく役職 | `g.leader`・`g.council` は役職。職業とは別。M5 の経歴でも `office`（役職）として別に記録 |
| 職業・身分・役職・所属を同じデータにしない | 経歴の種類を `office`／`rank`／`job`／`affil` に分けた（今日の修正）。身分 `rank` は、入れ物だけで中身なし |
| 市場・貨幣・ギルドの未確定部分を正式仕様にしない | 市場は物の出入りの記録だけ。値段・貨幣・ギルドは作っていない。外からの買い入れは「値段なし」と明記した暫定 |
| 既存の台帳・物流・所有を再利用 | 食料は台帳（整数）、輸送は既存の経路・荷の考え方、集落の関係値は既存の血縁・婚姻の記録を使用 |
| 民族・共同体・国家・言語は別の実体 | 民族 `ethnicities`（言語 `langId` も別）、集団 `groups`、国 `nation.js`（民族単位の集計）が別。民族IDは消滅後も歴史として残る |
| 民族の主所属と副次的な帰属 | `P.eth`（主）と `P.ethSecondary`（副次）。人物の出自の民族も保持 |
| 国家以前から政治がある | 集団の首長・合議・継承・指導者の決め方（長老制・能力制・世襲・合議）が、国とは別にある |
| 近距離は詳細、遠距離は集約。履歴・資源の整合性は維持 | 集計の層（`Cohort`）：遠い大きな集団は集計、近くは個人。降格しても個人IDを残す（cause=98）。台帳の収支の恒等式は全集団でちょうど0 |
| 同一Seedで結果を検証 | `test-budget`・`test-careers` など、同じSeedの再現を確認 |
| 既存カタログを勝手に削除・再生成しない | 思想のカタログは、リポジトリに無いので、触っていない |

## 2. 不足している部分（資料にあるが、未実装）
| 資料 | 状況 | 進め方の案 |
|---|---|---|
| 兼業（職業の掛け持ち） | 人物の職業は1つだけ（`P.job`） | 副職 `job2` を足す案。人物の保存形式が変わる（承認が要る） |
| 教育・資格（家庭・徒弟・共同体・学校・独学、識字と技能の区別、官僚の学問要件） | 「学ぶ」活動と、教わる（`forage.js`）はある。識字は文字の技術のみ。資格・学校・徒弟は無し | 識字を人物の属性として分ける案（承認が要る） |
| 身分・社会階層（貴族・平民・奴隷・自由民など） | 無し。経歴の `rank` は入れ物のみ。資料も「全社会に同一の階級制度を設けない」「詳細未確定」 | 思想（身分・階層9種）から、共同体ごとに身分制度が生まれる形にする。最初は何も置かない |
| 財産・経済力（個人・世帯） | 食料は集落の蓄えのみ。個人・世帯の財産・所有権は無し（欲求に「財産」はあるが、持ち物の量はプレイヤーだけ） | 世帯の所有を台帳に足す案（承認が要る） |
| 実質的影響力・正統性・服従・政策の採択と執行の区別 | 人物の関係（信頼・好意・尊敬）と首長の選び方はある。権限と実際の服従の区別は無し | 国の設計（M6）で扱う |
| 市場の価格・購入の優先順位・注文集計と取引確定の分離 | 無し（資料も未確定） | 試作の知見（登録順で結果が変わる問題）を、実装時の必須条件にする |
| 貨幣・信用・利子 | 無し（資料も未確定） | 「非貨幣的交換・贈与・互酬」を先に。現在の助け合い（贈り合いの記録、関係値の恩）が、互酬の入口になる |
| ギルド・職能団体 | 無し（資料も未確定）。内部集団の試作（氏族・派閥・宗教集団）が、手元のリポジトリには無い | 試作を貼ってもらってから設計。職業の成立で自動生成はしない |
| 思想（10大分類・412種、支持率、伝播） | 無し。民族の文化は8つの値（`cult`）のみ | 正本が手元に無いので、推測で作らない。正本（名称一覧）を貼ってもらう |
| 国家の判定（組織の継続・統治の実行・管轄・対外的自律・維持する人員資源） | 無し | M6 で、実態を評価する方式で作る（下の矛盾を参照） |
| 政権・王朝・機関・管轄の区別 | 国は民族単位の集計のみ | M6 |

## 3. 矛盾している部分（決定：現行仕様を優先。変更しない）
| # | 資料 | 現在の実装 | 提案 |
|---|---|---|---|
| A | 「国家は人口・技術の一定値に達した瞬間に出現しない」「固定の国家発展ツリーを設けない」 | `tech.js` に、**「国家」の技術**（前提：首長制・記録・栽培、人口600以上）があり、民族が採用すると国家になる、という作り。技術の木に前提がある | 国家の技術は、判定の1要素（記録・組織の道具）に格下げし、資料の判定式（継続性・実行力・管轄・自律・人員資源）で評価する方式に置き換える。**大きな仕様変更で、承認が要る** |
| B | 同上（M4 での私の実装） | M4 で、階層（町・都市）の条件に、民族の持つ首長制・国家の技術を使った（`gov`）。矛盾Aの延長 | 承認後、A と同時に、観測できる統治の実態（首長の継続、合議の有無、蓄えの管理、受け持つ割合など）に置き換える。それまでは暫定 |
| C | 民族の分裂：「距離・年月・言語差だけで自動分裂させない」。交流の減少・文化の変化・自他の帰属認識・歴史的経験が要る | 離れた集団が、文化の距離・離れている年数・人口が条件をそろえると、**確率で分裂**（`ETHNO.SPLIT_*`）。帰属認識・歴史的経験は見ていない | 帰属認識（人物が自分の民族をどう認識するか）と共有された出来事を条件に足す案。分裂の仕組みの変更で、承認が要る |
| D | 民族の融合：「混住・婚姻しても自動的に融合しない」「元の民族が必ず消滅するわけではない」 | 接触年数・集団をまたぐ婚姻・文化の近さが条件で、確率で**融合し、元の二つの民族は両方消滅（`merged`）**、新しい民族ができる | 元の民族を残す選択（融合でなく、新しい共通の帰属を副次的な帰属として足す）を足す案。承認が要る |
| E | 距離の単位 | 集団の座標は実距離だが、生活圏の広さ・食料の面積あたりの量・国の層（`nation.js` の接触距離 450 など）は、古い単位（座標1つ≒3.33km）のまま | M2 で、分裂・移住・接触・近隣の距離だけを実距離に直した。国の層の距離と、生活圏の広さは、そのまま。M6 の前に、統一するか判断が要る |
| F | 経歴・市場の入れ物（M5 の土台） | 資料の分け方に合わせて、種類を `office`／`rank`／`job`／`affil` に直した（今日）。市場の種類は、助け合い・買い入れのみ | 矛盾なし |

## 4. 今後の扱い
矛盾 A〜D は、上の方針で**変更しない**（M4 の町・都市の条件も、現行の技術の木（首長制・国家）を使ったまま）。下は、「不足」を足すときの順番の案（保存形式が変わるものは、足す前に報告する）。

### （参考）当初の承認依頼の一覧
1. **矛盾A・B**：国家・町以上の条件を、「技術の有無」から「統治の実態」の評価に置き換える（M6 の核。M4 の暫定を直す）。
2. **兼業（副職）**と、**識字・教育の属性**の追加（人物の保存形式が変わる）。
3. **世帯・個人の財産と所有**の台帳（市場・貨幣・身分の前提）。
4. **矛盾C・D**：民族の分裂・融合の条件に、帰属認識を足す／融合で元の民族を残す。
5. **思想の正本（名称一覧）**を貼ってもらう（思想・身分・経済の元になる）。
6. 内部集団（氏族・派閥・宗教集団）の試作と、家計・市場の試作のコードや報告の場所を教えてもらう（再利用のため）。

矛盾 A〜D は、現行を優先すると決まったので、触れない。「不足」のうち、保存形式が変わるもの（兼業・識字・財産）は、足す前に報告する。
