# 人員配属台帳 P0b：接続契約

この機能は編制・階級・徴兵制度を決めない。既存人物と呼出側の部隊IDを参照する配属台帳を提供する。本作HTML・人口・職業・資金・実位置は更新しない。

## 正本とポート
- people.npc が人物の正本。人物ID0を含め、参照のたびに存在・生死を確認する。
- worldKey は呼出側の世界識別子。政治側でSeedから勝手に作らない。本作の保存との正式な結合はまだ未実施。
- resolveUnit(id) は呼出側の部隊正本を参照する。台帳では部隊や指揮官を生成しない。
- authorize(command) は読取専用・同期の権限照会。明示的なtrueだけを許可とする。未指定・例外は拒否。役職・階級・政治制度の独自ルールを置かない。

## 操作
assign/release は caller 指定のoperationId、actorId、unitId、personIdsを受ける。成功前に全件を検証し、1人でも無効なら全件無変更。1人物は1つの常設配属先のみ。一時的指揮権・兼務は別の未実装概念で、常設配属の複製で表さない。

配属と実際の集合は別。台帳は実位置・職業・住居を変更せず、部隊の現地人数を生成しない。死亡しても人物は人口側に残り、配属からの解除は同じIDへの操作で行う。

成功操作はoperationIdと正規化内容を保存する。同じID・同じ内容は再適用せず、異なる内容の再利用は拒否。失敗操作はコミットされず、その後の再試行を禁止しない。任意のexpectedRevisionは競合検出用で、政治的な優先順位を意味しない。

成功時の技術的な事実はoutboxへ残す。pendingEvents/acknowledgeEventは履歴接続用。外部台帳での一度だけの反映には、外部側も同じoperationIdを受け付けて重複を防ぐ必要がある。現段階で世界の履歴・思想へ配信済みとは扱わない。

## 保存
形式version1の独立sidecar。世界の保存形式を変更しない。旧セーブにsidecarが無い場合は空の台帳で開始できる。読込時は形式・worldKey・全参照・名簿・操作重複を検証し、不正なデータを一部だけ適用しない。人口側の死亡・所属変更等は上書きしない。読込は既存台帳をin-placeで壊さず、新しい台帳の構築として返す。

## 完了条件
実Populationを使い、二重配属、権限不足、混合バッチ、死亡・不存在、操作再送、保存往復・異なる世界・不正データ、outbox再送を検査する。元のPopulationのn/checksum/RNG/位置・職業・人口統計を変えない。開発用画面は隔離されたテスト世界と明記し、本作の戦争完成とは報告しない。

実装上の境界：現在はアクティブな世界ごとに台帳を1個だけ保持する接続契約であり、部隊ごとに別の台帳を作ってはいけない。複数プロセスをまたぐ正本・トランザクションは未接続。人口オブジェクトが読み込みで差し替わった場合、古いアダプターは書き込み・保存を拒否する。履歴の復元は当時の承認済み操作を再構成し、現在の指揮官の権限で過去を再承認しない。台帳内に死亡者が残ることは生存や任務参加を意味しない。

検査：既存Populationによる15件を実行し、再入呼出し、権限照会中の部隊状態変更、世界参照差替えも拒否することを確認。従来の人物参照6件・交通11件も合格。未実装の在庫・徴募適格性・実移動・本作保存・歴史への配信を完成扱いしない。
