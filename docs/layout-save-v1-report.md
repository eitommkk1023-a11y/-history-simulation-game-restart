# 第2工程 2C：集落配置と歴史の保存（報告）

## 調べて分かったこと（以前の棚卸しの訂正）
`docs/audit-v1.md` に「集落の配置（`g.layout`）は保存せず、毎回作り直している」と書いたが、**誤り**だった。配置は集団のデータの一部として、すでにセーブに入っていた（別セッションの保存→読み込みで、建物の位置・形・道・水場が一致することを確認）。
本当の問題は別にあった：**施設を建てたとき・畑の広がりの段階が変わったときに、配置を `null` にして作り直していた**。世帯が変わった後の再生成で、建物の位置が変わりうる。また、履歴（いつ・誰が・何のために建てたか）はどこにも残っていなかった。

## 実装
- **配置を作り直さない**：施設の完成では何もしない。畑の段階の変化は、建物を動かさず畑だけ作り直す（`refreshFields`）。定住の段階が変わる（野営→村）ときの作り直しは、これまでどおり（別の暮らしの形になるため）。その移行は年表に残す。
- **集落の履歴（`layout.log`）**：成立（開始時点）・建設・空き家・再入居・廃屋・撤去・改築・解体・畑の変化。日は暦の絶対日、建てた・入居した世帯は世界共通ID（世帯＝夫の人物ID）。上限600件（古い所から捨て、成立の記録は残す）。
- **建物の記録（`b.rec`）**：建設日、建てた人（世帯ID）、目的、理由（新しい世帯／住民の要請／開始前から）、改修・再入居の欄、**推定かどうか**（開始前の歴史から作った建物は「推定」と明記。実際に起きた出来事とは区別）。
- **集落の年表（`g.chron`）**：開始時点・移住先に到着・半定住・村になる・飢えて離れる（日つき。上限80件）。成立の年月は、ゲーム内で成立した集落は日で、開始前からの集落は推定として記録。
- **世界共通ID**：建物ID＝集団ID×100003＋連番（集団IDから辿れる）。世帯＝夫の人物ID。
- **旧形式との互換**：`upgradeLayout` が、履歴・記録のない古い配置を補う（位置・向きは変えない）。保存の読み込み時に自動で実行。
- **集落詳細マップ**：選んだ建物に 建設日・建てた世帯・目的・改修を表示。集落の「歴史（記録）」欄に年表と最近の出来事を表示。

## 未解決・注意
- 野営→半定住→村 の移行時は配置を作り直す（建物は新しく建つ）。移行前の建物の痕跡を残すのは第4工程。
- 放棄された集落（移住で離れた集落）の配置は、いまは破棄される。廃墟として残す扱いは第4工程。
- 「建てた人」は、いまは世帯（夫の人物ID）まで。個人の職人などは、建設の仕組み（NPCの意思決定）が入ってから。
- 履歴に残るのは、集落の配置が生成された後の出来事。配置が作られる前（遠くの集落）の期間は、世帯の変化がまとめて一度に反映される。
- 検証用スクリプトは `tests-browser/`（ブラウザ用。実行にはPlaywrightとローカルのHTMLの配置が必要）。
