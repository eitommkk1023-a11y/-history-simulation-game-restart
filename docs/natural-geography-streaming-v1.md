# World of History — 自然地理の世界共通データ／チャンク／LOD 基盤 v1（試作）

## ステータス（2026-11-03）
- 今回の合意：世界全体の基本地形・河川・資源を生成して保持し、未訪問地域の民族／国家の歴史も進行させる。三人称3Dでは必要範囲をチャンク＋LODで表示する。地形変化は消さない。
- この追加コードは**独立した基盤モジュールの試作**。既存の `自然地理生成器.html`、`window.__geo`、既存の陸域／水域／気候／交通の動作は置き換えていない。
- 数値（128m区画・64分割・2m間隔、遠距離の段階、LOD半径、ノイズ振幅、スカート深さ、キャッシュ上限）は技術検証用の初期値で、ゲーム仕様の確定値ではない。
- 既存生成器は `W=H=3000`, `MESH_RES=512`。**縮小生成器（1500×1500）および広域256×256メッシュへの実変更は未実施**。本体側の多数の定数、陸地面積、地質／気候格子、テクスチャ、保存形式への影響を調べずに数字だけ変更してはならない。

## 基本アーキテクチャ
1. **正本の地理**：既存 `world.elev/type/biome/water/lakeId/lakeLevels/riverPts/riverStarts` を世界共通の基盤とし、描画から独立して保持。既存配列をコピーしない。
2. **共通座標**：原点=地図北西端、X=東、Y=南、単位m。既存セル(x,y)の中心は `((x+0.5)*metersPerCell,(y+0.5)*metersPerCell)`。ゲーム内の実寸座標と3D局所座標を分離。描画直前にカメラ近傍を原点に引き直し、遠距離のfloat32精度低下を防ぐ。旧Three.js広域描画座標との変換は今後の統合時に実装。
3. **決定的詳細地形**：粗い世界標高を双線形補間し、絶対世界座標＋Seedで決定する小規模ノイズを加える。同じ地点で再訪・LOD変更・再読み込みしても同じ高さになる。**粗い地形から現実の微細地形を復元できるわけではなく、詳細地形の生成品質には別途改善が必要**。
4. **チャンクとLOD**：128mを基準に、レベルnでは辺長 `128*2^n` の四分木タイル。タイルの標準分割数64なのでLOD0=約2m間隔。視点からの距離に応じて解像度を変え、常駐枚数を制限。隣接タイルの共有座標から同じ高さを採用し、段差の可能性がある解像度差は垂直スカートで目立たなくする。切替時の見た目の跳ね（モーフィング）は未実装。
5. **水系の連続性**：湖面標高は `lakeId/lakeLevels` に従う。河川の折れ線は `riverPts/riverStarts` を正本として、タイル境界で同じ位置にクリップして返す。川幅は既存の3要素目を利用。**実際の水流・河床掘削・河川の物理的な流路変化は未実装**。
6. **地形変化記録**：`id/day/kind/xM/yM/radiusM/deltaM` の空間イベントを追記し、元地形は書き換えず、問い合わせ時に加算。世界ID（Seed・寸法・セル寸法・生成バージョン）を検証してスナップショットを復元。イベントによる水系への影響は「再計算要」の状態を返すのみ。時間が進行しても自然に侵食計算する完成システムではない。
7. **読み込み・解放**：カメラが要求するタイルだけ非同期的に順次構築し、旧要求を無効化、キャッシュ上限内で使わないものを破棄。現試作の `setTimeout` はメインスレッドで仕事を小分けにする仕組みで、**本当のバックグラウンドWorker処理ではない**。スマホでのフレーム計測・適切なWorkerオフロードは次工程。
8. **交通・建築・NPCへの共通問い合わせ**：`sample(xM,yM)`・`conditions(xM,yM)` は標高・勾配・水域・生物群系を提供する。**通行許可・所要時間・建築可否・政治権限を地形側で勝手に決めない**。既存 `src/transport/geography-adapter.mjs` はブロック単位のまま保持。道路・橋・渡し場や人物の知識制限は交通側の責務として残す。

## API と用途
```js
import {createTerrainSystem,createTerrainTileCache} from './src/geography/terrain-streaming.mjs';
const terrain=createTerrainSystem(window.__geo.world, {
  seed: window.__geo.seedToInt(window.__geo.seed),
  metersPerCell: 3330, tileSizeM: 128, segments: 64,
});
const c=terrain.cellCenter(100,200);
const slope=terrain.conditions(c.xM,c.yM,4).slopeDegrees;
const cache=createTerrainTileCache(terrain,{maxResidentTiles:96});
const {tiles}=await cache.update({xM:c.xM,yM:c.yM,radiusM:8000});
// tiles[] の Float32Array 頂点／Uint16Array 三角形をThree.jsへ転送する表示コードは別途必要。
terrain.addEvent({id:'eruption-0001',kind:'eruption',day:100,xM:c.xM,yM:c.yM,radiusM:500,deltaM:18});
const save=terrain.serializeEvents(); // 既存保存台帳への接続は今後
```

## 統合の優先順と受け入れ条件
1. **生成器起動・計測**：低メモリiPhone Safariで既存 `3000×3000` 生成のピークメモリ／Worker転送時間を測定。1500×1500・256×256プレビューへの縮小は生成面積・陸地率・格子依存定数と合わせて安全に変更する。
2. **描画試験**：三人称カメラの近傍にだけ地形タイルをThree.jsで描画。既存の広域表示は維持し、タイルは旧メッシュの代わりに同位置へ重複描画しない。シャドウ・テクスチャ・インスタンス配置も計測する。
3. **水系統合**：細部地形と河川・湖面を合わせる。LOD境界の河川接続、上流から下流への勾配、改変後の再計算を専用テストにする。
4. **永続化統合**：実際の `serializeState/loadState` と地形イベントを結び、再ロード・数百年経過・集落破壊の回帰テストを通す。既存セーブデータを破壊しないバージョン移行を用意する。
5. **交通・建設統合**：道路ルート、橋、斜面、河川横断、建築物配置、地形改変、法制度・権限判定のデータを共通座標で結ぶ。
6. **世界歴史統合**：描画されない遠方の民族・国家・人口・交易・戦争は別の世界シミュレーションで更新し続け、訪問で状態を後付け捏造しない。
