# military-prototype-v1 報告（小さな野戦の試作）

**ゲーム本体（HTML）は変更していない**（試作は Node のみ）。ファイル：`npc/battle.js`、`npc/test-battle.js`、`docs/military-review-v1.md`（仕様書との突き合わせ表）。

## 目的
仕様書（軍事 Ver.2〜20）の中で、**一番難しいと見た部分**を先に確かめる：
- 戦術ボタンなしに、**配置・視界・命令・士気から**、陣形・偽装撤退・伏兵が自然に出るか
- **伝令**で命令が届く（遅れる・討たれる）、**情報が不完全**（伏兵は近づくまで見えない）
- 人物ごとのHPの戦闘が、**スマホで動く軽さ**か

## 作ったもの（仕様書との対応）
| 仕様書の原則 | 試作での実現 |
|---|---|
| 人物ごとのHP。HP0＝戦闘不能（死亡ではない）。向きで傷が変わる | 兵1人ごとにHP10。正面0.8倍（盾0.5倍）・側面1.0・背面1.6。向きを変える速さに限り（毎秒約1ラジアン）。「戦闘不能」で、死亡は別（試作は戦闘不能まで） |
| 武器の実態（長さ・射程・傷） | 槍（長さ2.4m）・剣（1.4m）・弓（射程70m、距離で当たりにくく、森では半減、動く的には当たりにくい） |
| 兵種は実態から（武器・防具） | 兵種の名前は無く、「武器＋盾の有無」の組合せで部隊を構成 |
| 士気・恐怖・退却 | 個人の士気。仲間が倒れる・背面から攻められる・四方のうち三方に敵がいる（包囲）で下がり、崩れて逃げる。敵が離れると回復 |
| 命令は受信・理解・実行に時間がかかる | **伝令**（毎秒6.5m）が指揮官から部隊へ走る。届くまで、部隊は前の命令（持ち場）で動く。敵兵が通り道にいると討たれる（30回中10回以上が失われる） |
| 情報は現実そのものではない | 兵は**自分の目で**見た敵だけ分かる（見える距離160m、森で止まっていると70m、**隠れた伏兵は35m**）。尾根と厚い森は視界をさえぎる。部隊が見た敵は、**15秒ごとの報告（伝令）**で指揮官へ届く |
| 指揮の強度（詳細指示／委任）、持ち場 | 命令は「持ち場を守る」「前進」「撤退」「伏兵」「偽装撤退（待つ→接触→交戦→引く→反転）」。届かなくても部隊は**持ち場の考え**で動く。**規律**が低い部隊は、引く敵を深追いし、高い部隊は持ち場を離れない |
| 戦術はボタンではなく、配置・移動・情報の組合せ | **偽装撤退も伏兵も、専用の補正は無い**。おとりが引く・伏兵が隠れて、敵が罠に入ると自分で判断して飛び出す、という「命令と持ち場の考え」だけで起きる |
| 戦争モードがない | 戦場は、世界と同じ地面・同じ時計。専用の画面・開始/終了イベントなし（試作は、片側が崩れたら記録するだけ） |

## 検証（21件すべて合格）
- 向きによる傷（正面・側面・背面）、向きを変える時間。
- 伝令：約300mで届くのは40〜60秒後。届くまでは前の命令。討たれる。
- 視界：隠れた伏兵は200mから見えず、近づくと見つかる／飛び出す。尾根と厚い森が視界をさえぎる。
- 士気：囲まれた部隊は、一方向から攻められた部隊より崩れる。
- **偽装撤退と伏兵（本題）**：A（西の軍：命令どおり前進し、規律が低く敵を深追いする）vs B（東の軍）。各軍60人・24回ずつの統計。
  | Bの戦い方 | Bの勝ち | A損害÷B損害 | Aの背面・側面の損害 |
  |---|---|---|---|
  | 持ち場を守るだけ（基準） | 0% | 0.52 | 3.9人（損害の16%） |
  | **偽装撤退と伏兵** | **63%** | **1.97** | **5.8人（損害の27%）** |
  - 伏兵は、罠に入ったときだけ飛び出す：Aが罠に入るとき24/24回、**Aが用心深く前進しないときは0回**（無駄に動かず、損害も0）。つまり「相手が餌に食いつくかどうか」で、罠が効くかが決まる。
- 決定性（同じSeedは同じ結果）。実際の世界の標高（1.6km四方・標高0〜145m）でも動く。
- **性能**：400人（20人×20部隊）の戦闘が、**1ステップ（0.5秒）あたり約3.4ms**（Node）。iPhoneで30fps（33ms）を保つ目安の約1/10。

## 試作の過程で見つけて直したこと（記録）
- 命令を受け取った時刻の欄が、おとりの「引く先」と同名で上書きされ、おとりが敵の方へ撤退していた。
- 敵が引いているかの判定が、見え隠れする敵の位置の平均に引きずられて誤判定していた（近くの敵の速度の平均に変更）。
- 向きを一瞬で変えられたため、側面攻撃が効かなかった（旋回の速さに限りを付けた）。
- 罠の位置が敵の進む筋に近すぎて発見されていた（発見距離より遠く）。

## 設計上の気づき
1. **罠の成否は、地形と相手の性格で決まる**：隠れ場所（森）が必要、相手が深追いしなければ効かない。固定の補正ではないので、世界ごと・相手ごとに結果が変わる（仕様書の「戦術の固定補正なし」と一致）。
2. 計算の軽さは十分。人物ごとのHPでも、**近くの数百人は人物ごと**で動かせる見込み。遠くは集約（仕様書の近傍詳細・遠方集約）。
3. **敵の指揮官AI**：今は決まった台本（偽装撤退）か、前進だけ。「相手の動きを見て、罠を選ぶ・避ける」AIは次の課題（最も難しい部分）。

## 未実装・限界（仕様書との差）
- 負傷・救護・捕虜・降伏・再集結（HP0は戦闘不能までで、その後は扱わない）、疲労、水・食料（兵站）、天気・時間帯の効果。
- 任命・兵員の割当て（Ver.12）：試作の編成は固定。階層・指揮官個人の能力は無い（指揮官は動かない点の指令役）。
- 敵指揮官のAI：伏兵と偽装撤退は台本。敵の意図を推測して罠を避ける判断は未実装。
- 戦場の被覆（森・低木）は試作では手で置いた円。世界の植生との接続は未実装。
- 係数（速度・傷・当たり・士気）はすべて暫定。**実機（iPhone/iPad）での描画・操作は未確認**（試作は計算のみで、画面表示はまだ作っていない）。
- 攻城・海戦・封鎖・上陸・外交の軍事（仕様書 Ver.15〜20）は、この試作の範囲外。
