# ロードマップ v1：まず基盤（機能を詰め込む前に）

目的：中世・近世を舞台に、プレイヤーが「個人として」生きながら「国として」育て、大都市（最終的に100万人規模）を目指せるゲームの土台を作る。
方針：**機能を足す前に、どの規模でも使える基盤を固める。** 機能（食料の輸送・衛生・統治・市場など）は、基盤の上に1つずつ載せる。

## 0. 現在地（正直な整理）
作業ブランチ `claude/small-world-v1`（mainは未変更）。

**できている**
- 小規模統合ワールド：窓（20/40/80km）の段階 S1〜S3 と、S4（世界全体）。初期の村 100〜500人。
- 観察（神モード）：時間の進め方、統計、ランキング、性能モニター、UIの表示切り替え、出来事の通知抑制。
- 見た目：木3種、川（源流・支流・河口・三角州・遠景）、湖・海の水際と大陸棚、地形の多様さ。
- 土台：保存の圧縮（約3.7MB→約0.6MB）、集落配置の高速化（約9000人で18秒→4秒、結果は一致）、実機の性能診断ボタン。
- 人口の層化：集計の層（`pop-cohort.js`）、世帯ごとの降格・昇格、自動の方針（`ctx.layers`。通常のプレイには未接続）。

**確かめられていない**
- iPhone/iPad 実機での動作・FPS・メモリ・発熱（診断ボタンの出力が未取得）。
- 描画・見た目の多くは、ヘッドレス（ソフト描画）の画像だけで確認。

**分かっている弱点**
- 集団ごとの計算（狩猟・植物の食料）が重い（100集団で約16ms/月）。集団が千を超えると破綻する。
- 世界が小さい（約100km四方・陸地約4,400km²）。中世〜近世の世界全体の人口は約10〜30万人が上限で、100万人都市は届かない（設定値で広げる前提）。
- 食料は狩猟採集・農耕・牧畜まで。輸送・貯蔵・衛生・統治・市場は未実装。集落の段階は「野営・半定住・村」のみ。
- 開始直後の人口の揺れ（初期人口が食料の支える水準より多い）。
- 集計の住民は、友人・結婚・技能を持たない。

## 1. 基盤の工程（機能より先）
各工程に「成果物」「合格条件」を置く。合格条件を満たすまで、次の機能に進まない。

### F0. 足元を固める（小）
- 成果物：実機の診断結果の取得（監督が診断ボタンを押して貼る）。テストの一括実行（node・ブラウザ）。mainへ取り込む手順の整理。
- 合格：実機で FPS・月の計算・メモリ・保存時間の基準値が分かる。テストが1コマンドで回り、結果が記録される。
- 注意：mainへのマージ・公開は、監督の承認が要る（約束）。

### F1. 設定値の切り出し（小）
- 成果物：世界の広さ（1マスの大きさ）・密度の上限・段階（S1〜S4）・初期人口の範囲・外との交易の量を、1か所の設定に集める。
- 合格：設定を変えるだけで、世界の広さ・規模が変わる（ただし、広い世界は別工程の検証が要る）。同じ設定・同じSeedで同じ結果。
- 理由：PC を買ってから世界を広げる前提。今は小さい世界のままで進める。

### F2. 人口の層化を完成する（中）
- 成果物：方針を通常のプレイにつなぐ（近さ・関係・役職・出来事）。保存形式の互換（旧保存を読める）。婚姻などの補正（個人との差を縮める）。集計の住民の職業・身分の集計（生産・経済に使う）。
- 合格：通常のプレイで、総人口が保存される・個人IDと履歴が壊れない・プレイヤーの近くは全員が個人。旧保存が読める。集計がある集団と個人だけの集団で、人口の推移の差が小さい。
- 状況：集計の層・昇格・降格・自動の方針は実装済み（node 23項目）。接続と保存互換が残り。

### F3. 集団ごとの計算の軽量化（中）
- 成果物：遠い集団・小さな集団は、毎月でなく間引いて計算する（近い集団は毎月）。食料（狩猟・植物）の計算を、集団の数に比例させない仕組み（地域単位の集計）。
- 合格：集団が1000を超えても、1か月の計算が予算（目標：実機で83ms未満＝1年/秒）内。近い集団の結果が、今と同じ。
- 理由：個人を減らしても、集団ごとの計算が残る（測定済み）。大都市・多数の集落には必須。

### F4. 時間と更新の枠組み（中）
- 成果物：更新の予算（フレーム・月）を管理する仕組み（重い処理を複数フレームに分ける）。重要度に応じた更新の頻度（近い・重要＝毎月、遠い＝年）。
- 合格：端末が遅くても、操作の反応が保たれる（自動の解像度調整に加えて、計算の間引き）。
- 注意：本来のゲームはリアルタイム。速さの変更は開発者向け（神モード）。

### F5. データの土台：集落の階層と台帳（中）
- 成果物：集落を「村・町・都市…」の階層として持つデータ構造。集落ごとの台帳（食料・材料・人口・身分の構成）。食料の0.1単位モデルの土台（次の工程でつなぐ）。
- 合格：既存の集落（野営・半定住・村）が、新しい構造で動く。既存の個人ID・血縁・所有・履歴が保たれる。
- 注意：この段階では、新しい機能（輸送・衛生など）の中身は作らない。入れ物と台帳だけ。

### F6. 保存の版管理と移行（小〜中）
- 成果物：保存形式の版番号と、旧版→新版の変換。圧縮・破損の検出。
- 合格：古い保存が読める。新しい項目がなくても動く。破損したら、安全に失敗して知らせる。

### F7. 描画の土台（中）
- 成果物：大きな集落の描画（街区単位の配置・遠景の簡略化・まとめて描く）。遠景の水・地形・木の段階的な簡略化の整理。
- 合格：約1万人の村へ飛んでも、実機で操作できる。描画の予算（三角形・呼び出し）が決まっている。

### F8. 検証の土台（小〜中、全工程で並行）
- 成果物：決定性（同じSeed）・不変条件（人口の保存・IDの整合）・性能予算の自動検査。主要な見た目の基準画像（スクリーンショット）。
- 合格：変更のたびに、これらが自動で確認できる。

## 2. 基盤のあとで機能を載せる順番
基盤の上に、1つずつ。各機能は、既存の仕組みを再利用し、重複させない。

| 段 | 機能 | 目安の人口 | 前提の基盤 |
|---|---|---|---|
| M1 | 食料の貯蔵・余剰（0.1単位）、農耕の発達 | 〜1万 | F5 |
| M2 | 食料の輸送（道・川・港・船）、町の成立 | 〜10万 | F3, F5, F7 |
| M3 | 水と衛生（疫病・都市の頭打ち） | 〜10万 | F5 |
| M4 | 統治・財政（税・役所・備蓄・治安）、都市の段階（町・都市） | 〜30万 | F2, F5 |
| M5 | 市場・貨幣・同業組合、職業・身分（個人の道） | 〜30万 | F2, F5 |
| M6 | 国（領域・外交・財政）。自律的な軍事は既定で無効のまま | 国単位 | F3, F4 |
| M7 | 世界の拡張（PC向け）。外との交易 | 〜100万 | F1, F3, F7 |

「個人として」の道（職業・身分・財産・人脈）は M5 から本格的に載せる。基盤（F2）の層化が前提。

## 3. 守る約束（全工程）
- 既存の個人ID・血縁・所有・履歴を保つ。同じSeedで同じ結果。
- 既存の仕組みを再利用し、重複して作らない（観察のための別モードを作らない等）。
- 未実装を実装済みと報告しない。実際に走らせたテストの件数だけを報告する。
- 自律的な軍事は既定で無効のまま。戦争・移住は強制しない。
- 食料の0.1単位モデルは、M1 で扱う（それまでは今のモデル）。
- 作業は、専用ブランチで小さなコミットにする。mainの変更・公開・マージは、監督の承認が要る。
- iPhone/iPad の横画面を優先する。

## 4. 決めること（監督へ）
1. 基盤の工程の順番（F0→F8 のどれを先にするか）。提案：F0→F1→F2→F3→F5→F6→F4→F7（F8 は並行）。
2. F0：実機の診断を、いつ・どの端末で取るか。
3. 世界の拡張（M7）の時期：PC を買ってから。それまでは小さい世界で、F1 の設定の切り出しだけ行う。
4. mainへ取り込む時期（F2 完了時など）。
