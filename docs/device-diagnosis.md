# 実機の性能診断（iPhone/iPad）の手順

目的：実機の基準値（FPS・1か月の計算・保存の圧縮時間・メモリ）を取り、描画・計算・保存の優先順位を決める。ヘッドレス（ソフト描画）の値は実機とは別物なので、実機の値が必要。

## 準備
- 最新の試験版を開く（チャットのArtifact、または `World-of-History-small-world-trial.html`）。
- iPad/iPhone を**横画面**にする。他のアプリを閉じ、充電が十分な状態で、低電力モードはオフにする。

## 手順（約3分）
1. タイトルの左側で、段階を選ぶ（まず **S1**。次に **S3**、余裕があれば **S4**）。
2. 「小規模ワールド（試験）」を押す。世界ができるまで約20〜40秒待つ（この時間も控えておく：端末の起動時間）。
3. 神モードの右側の操作盤を下へ送り、「性能モニター」を開く。
4. 「**実機の性能診断（約25秒）**」を押す。25秒ほど、画面に触れずに待つ（視点が、近い・中・遠いと自動で動く）。
5. 下の枠に文章が出る。「診断おわり」と出たら、枠の文章を**全部コピーして貼り付けて**ください（自動でクリップボードにも入る）。
6. 段階を変えて（S3、S4）、2〜5を繰り返す。

## 一緒に教えてほしいこと
- 端末の名前（例：iPad Pro 11インチ 第3世代、iPhone 14 など）と iOS のバージョン。
- 世界の生成にかかった時間（手順2）。
- 体感：操作がカクつく所（近づいたとき・引いたとき・大きな村へ飛んだとき）、発熱、落ちたかどうか。

## 出力の見方
| 項目 | 目安（合格） | 意味 |
|---|---|---|
| 描画のFPS（近い・中・遠い） | 30以上 | 描画の滑らかさ。低い所が、描画の最適化の対象 |
| 三角形・呼び出し | 近い 20万・遠い 15万 程度 | 描画の重さの目安（実機のFPSと見比べる） |
| 1か月の計算 | 83ms未満（1年/秒） | 世界の計算。S3・S4 で超えると、計算の軽量化（F3）が必要 |
| 保存の圧縮 | 3秒未満 | 長い待ちが出る場合は、圧縮の見直し |
| メモリ | 端末の上限の半分以下 | 超えると落ちる。保存・世界データの見直し |

ヘッドレス（ソフト描画・参考値）：近い 3.5FPS・中 7.2・遠い 3.0、1か月 57ms（S1）、圧縮 5.3秒、メモリ 308MB。実機はこれより速いはず。

## 大きな集落の描画テスト（F7）
神モードの「大きな集落の描画テスト（約50秒）」ボタン。いちばん人口の多い村へ飛び、その村の建物を複製して 500／2000／5000棟に増やし、近い視点（150m）と引いた視点（450m）で FPS・三角形・呼び出し・描いた建物数を測って、文章で出す（自動でコピー）。終わると元の村に戻る。
- 増やした建物は一時的なもので、保存の前に必ず解除される（保存・世界には混ざらない）。人は増やさない。
- 建物は中心から 430m（DW_RANGE）までしか描かない。複製は外へ広がるので、5000棟では外側が切れて約3300棟が描かれる。上限（DW_CAP）に当たったときは「（上限:種類）」と出る。
- 目的：実機のFPSで、描画の予算を決める／街区単位の描画が必要かを判断する。
- ヘッドレス（ソフト描画）の値は参考外（0棟でも約4FPS）。実機の数字を貼ってもらう。

### 数字の読み方（2026-11-17 改訂）
- FPS は requestAnimationFrame の回数で数える（以前は描画の回数で、60を超える値が出ていた）。iPhone は画面の更新が上限（60 または 120）。
- 最長：いちばん長かった1フレーム（ms）。カクつき：33ms を超えたフレームの数。描画命令：描画の命令を出すのにかかった CPU 時間（1フレームの平均）。FPS が上限に張り付くときは、こちらで余裕を見る。

### 実機の記録（iPhone 17、2026-11-17、旧方式の FPS）
建物 0〜5000棟、近い（150m）でも引いた（450m）でも、約60FPS。三角形は最大 約41万。引いた視点で建物 0 なのは、村人LODの不具合（修正済み）のため。

### 実機の記録（iPhone 17、2026-11-18、新方式）
建物 0〜5000棟（描けたのは3287棟：当時は描く距離 430m 固定）。全体で 57.8〜59.2FPS、最長 46〜62ms、カクつき 1〜2回／3.5秒、描画命令 1.4〜1.9ms、三角形 30万〜58万、呼び出し 43〜61。余裕は大きい。
→ 描く距離を引いた高さに合わせて広げ（最大1000m）、部品の上限を5000棟分に引き上げた。

### 実機の記録（iPhone 17、2026-11-18 7:42、描く距離を広げた版）
引いた(450m)で 5000棟すべてを描画：55.7FPS・最長 39ms・カクつき 2回・描画命令 1.6ms・三角形 61万・呼び出し 64。その他は 57.9〜59.7FPS。
→ 三角形 約60万が、約60FPSを保てる上限の目安（ここから FPS が下がり始める）。F7 は完了。
