## 位置づけ
- 仕様の出典：船舶システム設計 引き継ぎ資料（Ver.1〜22）のうち **Ver.4（断面による船体形状）・Ver.6（質量と重心）・Ver.7（浮力と復原性）** の最小部分。

- 係数・試作船の値は**試作値**であり、承認された仕様でも史実の諸元でもない。

## 座標系・単位（船体固定、SI単位）
| 軸 | 向き |
|---|---|
| x | 船の長さ方向（m、船首側が正） |
| y | 幅方向（m、右舷が正） |
| z | 高さ方向（m、上が正。0はキール下端の基準線） |

- 横傾斜（ヒール）は右舷が下がる向きを正、縦傾斜（トリム）は船首が下がる向きを正とする。
- 水の密度は海水1025、淡水1000 kg/m³。

## ファイル構成
| ファイル | 内容 |
|---|---|
| `hull-geometry.mjs` | 横断面（高さzと半幅bの制御点）を船首尾方向に並べ、断面の間を線形補間。チャイン（折れ目）は保持される。物理計算用の形状で、描画用メッシュとは別。 |
| `mass.mjs` | `M=Σm`、`G=Σmr/Σm`。同じIDの重複を拒否する（二重計上の防止）。 |
| `hydrostatics.mjs` | 実際の水中形状から排水容積と浮心を求め、トリムを自由にした釣り合いを解く。喫水、トリム、KB・BM・GM、GZ曲線、開口部の浸水角、重心が中心からずれたときの静的傾斜を出す。 |
| `ship-model.mjs` | 最小の船データ `createShip`。乗員・貨物・所有者は既存台帳へのID参照（refs）だけを持ち、複製しない。 |
| `samples.mjs` | テスト用の箱形船と、ガレオン風の**仮の**船体。 |

## 利用例
```js
import { createShip, analyzeHydrostatics } from './src/ship/index.mjs';
import { galleonLikeHull, galleonLikeMassItems } from './src/ship/samples.mjs';
const ship = createShip({ id: 'ship-1', hull: galleonLikeHull(), massItems: galleonLikeMassItems(),
  openings: [{ id: 'gunport-stb-1', x: 20, y: 5.3, z: 5.2 }] });
const r = analyzeHydrostatics(ship); // 海水、0〜90°を5°刻み
r.upright.draftMid; r.upright.GM; r.gzCurve; r.downflooding;
```

## テスト
```sh

```
- 箱形船を解析解と照合した：排水容積、喫水2.0m、KB=1.0、BM=1.5、GM=0.5、舷側が垂直な船体の公式によるGZ（10°・20°）、静的傾斜角。
- トリムについては、浮心と重心が地球の鉛直線上に並ぶことを確かめた。
- 淡水では海水より喫水が深くなること、浸水角は沈む側の開口部だけに出ること、過積載なら浮力不足を返すことも確かめた。

## 制約・未実装（次段階以降）
1. 船体は甲板・舷縁まで水密と仮定している。開口部から実際に水が入る計算、内部の水、自由表面効果はまだない（Ver.17と統合する際に、浮力の喪失と水の重さを二重に数えない方式を決める必要がある）。
2. 静水中の静的な釣り合いだけを扱う。波・風・6自由度の運動はまだない（Ver.8・9）。
3. 左右対称の単胴船だけに対応する。双胴船・アウトリガー・左右非対称の船体は未対応。
4. 横傾斜とトリムの組み合わせは、水面の法線ベクトルで近似的に表している。90°を超える大角度での精度は未検証。
5. 断面の保存形式や制御点の数は、資料§18の「未確定事項」にあたる。今回の形式は暫定。
6. 本体への統合（世界座標・自然地理の水深・風・人口ID・在庫台帳）はまだ行っていない。

# 第2段階：浸水（Ver.17の最小部分）
実装：`src/ship/flooding.mjs`　検証：`tests/ship-flooding.test.mjs`

## 方式
- 区画は船体固定の直方体。区画どうし、または区画と海を結ぶ「開口」（面積・高さ・位置・開閉）を置く。
- 開口を通る流量は `Q = Cd × A × √(2gΔh)`（Cd=0.6）。時間は一定刻みで進める。
- **水は「重さ」としてだけ数える。** 浮力は船体の外形だけから出す。浮力の喪失と水の重さを二重に数えない（資料§4.2の要検証点への暫定回答）。
- 区画内の水面は地球に対して水平。傾くと水の重心が動き、自由表面効果が自然に出る。
- 毎ステップ、傾斜とトリムの釣り合いを解き直す（準静的）。

## 結果の状態
`afloat`（浮いている）／`sunk`（浮力不足）／`capsized`（安定な釣り合いが見つからない）。一度なると以後は進まない。沈没船の履歴保持は未実装。

## テストで確認したこと
- 閉じた区画には水が入らない。
- 底の穴から浸水した箱形船が、解析解どおり喫水2.5m・内部水60m³・内外の水面一致に落ち着く。
- 水量が保存される（海からの流入＝区画の増加、区画間の移動で総量が変わらない）。
- 片舷の浸水でその舷に傾く。
- 同じ重さでも、固定の荷より動く水のほうが大きく傾く（自由表面効果）。
- 船幅いっぱいの大区画の浸水は、安定を失って転覆または沈没と判定され、喫水を返さない。
- 不正な入力の拒否。

## 制約・未実装
1. 区画の天井からのあふれ、空気の閉じ込め・抜け、区画内の仕切りは未対応。区画は満水で流入が止まるだけ。
2. 開口の流量式は試作の近似。水面が開口にかかる途中の扱いは粗い。要検証。
3. 波・動揺・動的な転覆は未対応（静的な釣り合いの連続のみ）。
4. 排水（ポンプ）、応急閉塞、火災、乗員の対応、認識と実際の分離は未実装。
5. 区画は直方体のみ。船体形状に沿った区画は未対応。
6. 処理は1ステップ約5ms（箱形船1隻、PC上）。iPhoneでの負荷は未測定。多数の船を同時に計算する前に最適化と、遠距離用の簡易計算が必要。

# 第3段階：船の動き（水の抵抗・帆と風・舵）— Ver.8・9・11の最小部分
実装：`src/ship/hull-params.mjs`、`src/ship/dynamics.mjs`　検証：`tests/ship-dynamics.test.mjs`
**すべての係数は試作値で、実測や史実に合わせて調整したものではない。**

## 座標・向き
世界座標は X=東、Y=北（m）。船首方位は北から時計回り。船体は x=前、y=右舷。旋回速度 r は右舷へ回る向きが正。

## 内容
- 船体抵抗：摩擦（ITTC1957式）＋形状＋簡易な造波。速度は推進力と抵抗の釣り合いで決まり、船型ごとの最高速度は置いていない。
- 横流れ：竜骨の揚力と横流れ抵抗、旋回の減衰。
- 舵：舵角と舵位置の水流から横力を出し、回頭モーメントにする。舵は一定の速さでしか動かない。
- 帆：見かけの風（風−船の対地速度）に対して、帆ごとの面積・向き・縮帆率・位置・高さから力を出す。`square`（横帆。帆をセンターラインに近づけられる限界が大きい）と `foreAndAft`（縦帆）の2種。
- 傾斜：帆の横力による傾けるモーメントを、第1段階の復原力曲線（GZ）に当てて傾斜角を求める。傾斜すると帆の力が減る。復原力の最大を超えると `overpowered` を立てる。
- 海流：船は水に対して動くので、海流があれば流される。
- `autoTrim`：各帆を前進力が最大になる角度へ調整する（船長AIの代用）。`steerTowards`：指定の方位を保つ簡易な舵取り。

## 数値の目安（ガレオン風の試作船、風速10m/s、帆面積500m²）
| 船首方位（風上0°） | 縦帆の風上方向速度 | 横帆の風上方向速度 |
|---:|---:|---:|
| 30° | +2.4 m/s | −1.0 m/s（登れない） |
| 40° | +2.8 m/s | +1.4 m/s |
| 60° | +2.3 m/s | +2.1 m/s |
縦帆のほうが風上に登れる、という方向は出ているが、**数値は実在船より風上に登りすぎている可能性が高い**（横流れも小さめ）。

## テストで確認したこと
- 風がなければ減速するだけで、横に流れたり後退したりしない。
- 縦帆は風上に進み、横帆は同じ方位では進めない。追い風では風速より遅い。
- 右舵で右へ、左舵で左へ回り、左右対称。舵なしなら直進。旋回半径は船長の1〜8倍の範囲。
- 横風で風と反対側へ傾き、左右反転で符号も反転する。巨大な帆は `overpowered`。
- 縮帆で帆の力が半分になる。海流で無動力の船が海流の速度で流される。
- 同じ条件で同じ結果（再現性）、有限値。

## 制約・未実装
1. 6自由度のうち前後・横・回頭の3つだけ。横揺れ・縦揺れ・上下は動的には扱わない（傾斜は静的に求める）。
2. 波、浅水域の影響、うねりによる抵抗増加は未対応。風・海流は呼び出し側から渡す値で、既存の気象・海洋データとは未接続。
3. 帆のはためき（ルーフィング）、帆どうしの遮蔽、帆の失速の精密な扱いは未実装。
4. 櫂・艪・棹（Ver.10）、錨・係留・座礁（Ver.12）は未実装。
5. 帆の操作は即時で、船員の作業時間・人数・技能は反映していない。
6. 帆の位置は船体中心線上と仮定している。

# 第4段階：櫂・錨・座礁（Ver.10・12の最小部分）
実装：`src/ship/dynamics.mjs` に追加　検証：`tests/ship-anchor-ground.test.mjs`　試作船：`samples.mjs` の `galleyHull`（約36mのガレー風）
**係数はすべて試作値。**

## 櫂（人力推進）
- 左右の漕手グループ（`oars`）ごとに人数・位置・出力設定（−1〜1。マイナスは逆漕ぎ）を持つ。
- 推力 = 効率×出力 ÷（船速+0.5）。1人あたりの出力は120W、効率0.6、同調0.9（試作値）。
- 疲労：全力だと約10分で体力が尽き、出力は4割まで落ちる。休むと回復する。
- 左右で出力が違えば旋回する。帆との併用もできる（力を足すだけ）。
- 試作ガレー（漕手100人）：全力で約3.2m/s（約6kt）、10分で約2.5m/sまで低下。

## 錨
- 錨の重さ・錨索の長さ・海底の種類で保持力が決まる（保持力 = 係数×錨の重さ×重力×錨索の長さ/水深の比）。比が5未満だと保持力が落ちる。
- 錨索はバネとダンパーで、張力が保持力を超えると錨が引きずられて船が流れる（走錨）。破断張力を超えると錨索が切れる。
- 水深データ（`env.depth`）がなければ投錨できない。水深より錨索が短くても投錨できない。

## 座礁
- 水深を船首・中央・船尾で調べ、喫水より浅ければ接地する。海底が支える力は「失われた浮力」までで、船は浮力の分だけ海底に乗る。
- 摩擦で止まる。最初の接触で衝撃エネルギーを損傷指数（MJ）として記録する。**船体損傷や浸水への反映は未接続。**
- 水深が増えれば（潮位の上昇など）浮き、逆漕ぎで離礁できる。`grounded` `refloated` 等のイベントを返す。

## テストで確認したこと
- ガレーの速度が妥当な範囲、片側を強く漕ぐと旋回して左右対称、疲労と回復、逆漕ぎで減速。
- 重い錨は風で流される船を留め、軽い錨は引きずられる。海底が泥・錨索が短いと保持力が下がる。
- 水深が錨索より深い・水深データなしでは投錨できない。錨索の破断。錨を上げれば船は動き出す。
- 浅瀬に乗り上げると止まり、衝撃イベントと損傷が記録される。潮位が上がると浮き、逆漕ぎで離れる。

## 制約・未実装
1. 係留（岸壁・係留索）、接岸、ワーピング、曳航は未実装。
2. 潮位の生成は未実装（`env.depth` に時間を渡すだけ）。海底の傾斜による船体の傾き・縦傾斜は考慮していない。
3. 櫂の動き（漕ぐ周期・同調の失敗・櫂が波に噛む）や、漕手の座席ごとの配置は未実装。人数と出力で近似している。
4. 錨の揚げ下ろしに必要な船員の作業時間・人数は未反映（即時）。
5. 座礁の損傷を浸水・構造強度へ反映するのは未実装。

## 確認画面の更新ルール
機能を追加したら、`node tools/build-ship-viewer.mjs` で `ship-viewer.html` を作り直し、チャット内で遊べる公開ページも同じ内容に更新する。第4段階以降の確認画面には、ガレー（櫂の出力、体力）、錨の投下・揚収、浅瀬（北400m〜）の切替がある。

# 性能の数値合わせ（2026-11-05）
「できれば現実に近づけたい」への対応の第1段階。**基準値は、史実の船の性能についての一般的な知識から私が見積もった大まかな範囲で、出典のある実測値ではない。** 出典つきの数値が手に入ったら差し替える。

## 調整前のずれ（風速10m/s、帆面積500m²）
横風で約10kt（目安は6〜8kt）、横帆で風上に毎秒4kt登る（目安は1kt前後）、横流れ1度未満（目安は4〜12度）、傾斜2度（目安は2〜10度）。

## 調整したこと
- 船体抵抗：付着物・粗い外板による摩擦の割り増し（`roughnessCf`）、形状抵抗（`form`）、造波抵抗の強さ（`waveK`）を足した。
- 横流れ：船体の横方向の揚力係数を2から0.5へ。喫水が浅く長い船体は縦横比が低く、揚力が小さいため。
- 帆：横帆は帆をセンターラインへ寄せられる限界を32度から40度へ（風上に登れない）、揚力の立ち上がりを緩め、索具などの抗力を増やした。縦帆も抗力を増やした。
- ガレオンの帆面積を500m²から1200m²へ（排水量885tに対して小さすぎ、傾斜が出なかったため）。船体上部・索具の風圧面積150m²を追加。
- ガレーを漕手170人（左右85人ずつ）に。重さは34t。
- 調整値は設計データの `tuning` に持たせた（`samples.mjs`）。船の登録（`fleet`）、確認画面、本体の写しはこれを使う。

## 調整後（ガレオン、風速10m/s、帆面積1200m²）
| | 横帆 | 縦帆 |
|---|---|---|
| 横風・斜め後ろ風（80〜130度）の速さ | 6.9〜7.3kt | 7.4〜7.6kt |
| 追い風（180度）の速さ | 7.1kt | 7.3kt |
| 風上（40度）への前進 | できない | 約2.5kt |
| 風上へ最も登る角度での前進 | 約1.3kt（60度） | 約2.5kt（40度） |
| 横流れ（風上航行時） | 約9度 | 約10度 |
| 傾斜（横風） | 3〜4度 | 4〜5度 |

ガレー（漕手170人、出力70%）：2分後 約6.1kt、10分後 約5.6kt（体力が減って遅くなる）、全力で2分 約6.8kt。旋回半径は約48m（船の長さの約1.3倍）。

## 再現と確認
- `node tools/ship-calibration.mjs` で表を出力できる（パラメータの上書きも可）。
- `tests/ship-reference-performance.test.mjs` が上の範囲を検査する。範囲を外れる変更は失敗する。

## まだ現実とずれていそうな点
1. 追い風の速さが風上以外で頭打ちにならない。実際の船は風速に対して速さがもっと低いかもしれない。
2. 帆は今も自動調整で、帆を張る・畳む作業の時間や、向きの変更（タッキング）の失敗はない（次の候補：操船を現実的に）。
3. 波・うねりがなく、船の揺れがない。
4. 傾斜が小さめに見える（重心・復原力が実船より強い可能性）。
5. 風上への登り方は、帆の揚力・抗力の簡易モデルに依存している。実船の帆走性能の図（ポーラー）と照合していない。

# 船長AI（2026-11-05）— 「船員が操縦してプレイヤーは待つ」の第1段階
実装：`src/ship/captain.mjs`、`fleet.mjs`（`setDestination` / `cancelDestination`）　検証：`tests/ship-captain.test.mjs`（8件）
**すべて試作。出典のある仕様ではない。**

## できること
- **航路の計画**：水深の格子でA*探索し、一直線に行ける区間をまとめる。船の長さの2倍（80m）を浅瀬から離し、まとめた直線はさらに1.6倍離す（風で流されるため）。
- **帆走**：目的地が風上の航行不能な範囲にあるときは、風上へ交互に針路を変えて登る。縦帆はタッキング（風上側へ回頭）、横帆はウェアリング（風下側へ回って大回り）。横帆は1回ごとに大きく下がるため、風上への前進は非常に遅い（速度は実船でも遅いとされる範囲）。
- **出港**：向かい風で止まっている船は後ろへ流されるので、先に横風へ針路を取って速度をつけてから針路に戻る。
- **流される分の補正**：実際の進行方向（海流・横流れ）と船首方位のずれを測り、目的地に航跡が向かうように針路を補正する。
- **帆の管理**：1秒ごとに帆を調整し、傾斜が大きいと帆を絞る（縮帆）。落ち着けば戻す。
- **櫂**：帆のない船は漕ぐ。体力が減ると出力を落とす。
- **到着**：帆をたたみ、逆漕ぎで減速し、錨を下ろす。錨が下ろせない場所では、止まるか3分たつと到着扱い。
- **安全**：進行方向の先に浅瀬があれば、航路を引き直す（20秒に1回まで）。
- 船の保存データ（`fleet.serialize`）に船長の状態も入る。

## 本体の写しでの使い方
- 乗船中の下のバーに「目的地（俯瞰で指定）」「前方3km」「航海をやめる」を追加。
- 俯瞰の地図をタップすると目的地になり、航路（黄色い線）と目的地（黄色い球）が地図に出る。
- 航海中は、舵・帆・櫂を船長が操作する。手動の舵ボタンは「航海をやめる」を押すと使える。

## 確認したこと
- 追い風・向かい風（縦帆）で目的地に着いて錨を下ろす／横帆は風上へ少しずつ進む／島を避ける／行けない目的地は理由つきで断る／ガレーは体力を残して到着／強風で縮帆／保存して復元すると同じ航海が続く（テスト）。
- 本体の写し：「前方3km」で航路が引かれて動き出す（実際の世界、PCのブラウザ）。

## 制約・未実装
1. 船長は水深・風を環境から直接読んでいる。海図・知識・経験の仕組みはない（`knows` は将来の差し込み口）。
2. 帆の操作や針路の指示は即時で、乗員の作業時間・人数・技能・疲労は未反映。
3. 座礁すると自力では離礁しない（引き船や錨を使った離礁、潮待ちはない）。
4. 風上へ登る角度は、船ごとの帆走性能表ではなく、帆の種類ごとの固定値（縦帆42度、横帆58度）。
5. 航路は静的な水深だけで決まる。ほかの船、潮、天候の変化、季節風を利用した航路選びはない。
6. 遠くの目的地は格子が粗くなる（最大400m）ため、細い水路は通れない。
7. 俯瞰の地図タップは海面（高さ0）との交点を使う。陸や高地をタップすると、ずれた位置になることがある。
8. 風が弱い世界では、ガレオンはほとんど進まない。目安は風速2m/s未満。

# 船内の部屋（`src/ship/interior.mjs`、2026-11-05）— 「船の中を歩く」の第1段階
検証：`tests/ship-interior.test.mjs`（7件）。確認はテスト世界（`ship-sandbox.html`）。**間取りは試作で、史実の図面ではない。**

## データ
船の設計データに `interiorId` を持たせ、間取り（`samples.mjs` の `sampleInteriors`）はJSON。
- **甲板（decks）**：高さ（キール基準のz）を持つ。ガレオンは上甲板8.0m・砲甲板5.2m・船倉2.4m。ガレーは甲板1枚。
- **部屋（rooms）**：長方形（船体座標のx=船尾から船首へ、y=右舷が正）。同じ甲板の部屋は重ならず、壁の隙間を空ける。用途（`use`）は船長室・乗員区画・貨物・倉庫など。
- **扉（doors）**：壁の隙間にかかる長方形。向き（`along`）は壁が走る方向。
- **階段（ladders）**：2つの甲板の足場を結ぶ。近くにいると「上る／下りる」が出る。

## 動き
- 歩ける範囲は「部屋の床（プレイヤーの半径0.3mを引いたもの）＋扉」で、さらに船体の幅の内側。壁にぶつかると、壁に沿って滑る。
- 上甲板は船体の上面そのものを床とし、船体の幅と長さの内側に制限する。
- 船の揺れ（傾斜）は、プレイヤーを船の子として動かすことで自然に合う。

## 表示
- 甲板ごとに床と壁を作り、今いる甲板だけを表示する。上甲板より下にいるときは、船体が半透明になり、帆とマストを隠す（断面表示）。

## 将来への接続
- `toFloodingBoxes(topZ)`：部屋を、浸水の計算で使う区画（床・天井つきの箱）に変換する。浸水・火災・NPCの経路に同じ間取りを使えるようにするための口。まだ浸水計算には接続していない。

## 制約・未実装
1. 長方形の部屋だけ。傾斜した壁、曲がった壁、船体の形に沿った区画はない。
2. 扉は常に開いていて、開閉・施錠・破壊はない。家具・貨物・設備の配置もない。
3. 階段は瞬間移動（歩いて上る動きはない）。
4. 本体の写し（ゲーム本体）にはまだ入れていない。テスト世界のみ。
5. 保存データに、プレイヤーの船内位置は入っていない。

# ピンタ号（キャラベル）の再現（2026-11-05）
`samples.mjs` の `sampleDesigns.pinta`、間取りは `sampleInteriors.pinta`。**寸法・重さ・間取りは、一般的な復元の資料から見積もった大まかな値で、出典のある図面ではない。復元資料（復元船の実測、史料）と照合が必要。**

## 再現した特徴（写真の模型にならった）
- **円帆型のキャラベル**：主マスト・前マストは横帆（赤い十字つき）、後ろのマストは三角帆（ラテンセイル）。船首にバウスプリット、主マストの先に旗、船尾に一段高い船尾甲板。
- **船体**：全長21m、幅約6.4m、排水量約99t、喫水約1.7m、前後の傾きほぼなし、GM約1.95m。
- **帆**：主帆120m²、前帆55m²、後ろの三角帆60m²（合計235m²）。
- **船内**：船尾甲板／主甲板（外）／船尾の船室（低い天井、扉つき）／船倉（乗員区画・貨物）／食料庫。はしごで船尾甲板へ、昇降口で船倉へ。

## 追加した機能
- 三角帆（`lateen`）の種類：横帆より抗力が大きく、揚力は縦帆より小さい。
- 船長AIが、帆の面積で船の種類（横帆主体なら横帆の動き）を判断する。ピンタ号は横帆主体なので、風上へはウェアリングで登る。
- 表示：横帆の形（マストを中心に張る）、三角帆、赤い十字の布、バウスプリット、旗。船室には低い壁（高さ1.3m）、船尾甲板は上から床が見える。船室に入ると、天井の船尾甲板は隠れる。
- 部屋の属性：開放（`open`、壁なし）、床なし（`floor: false`）、壁の高さ（`wallHeight`）、天井を隠す甲板（`hideDecks`）。甲板の `exterior`（外の甲板）。
