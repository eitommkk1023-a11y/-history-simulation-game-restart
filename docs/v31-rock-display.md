# v31 地質表示の配色と凡例

ユーザーから「分布は適当か」「新しい表示の色と意味が分からない」と指摘されたため、生成規則を確認し、表示を修正した。新しい描画ライブラリは追加しない。

## 分布について確認できた事実

`world-rocks.mjs` は火山・造山・断層・地殻・気温・降水などで地域を分類する。その後 `layers.mjs` の14個の固定岩種セットと周期的な層テンプレートを割り当てる。岩種セットや層の順序は実装者が決めた簡略化で、冷却・堆積・変成の履歴を積み上げて推定した岩石分布ではない。

地質格子はソース世界で26,640m間隔、層の周期は典型的に118.75mまたは332.5m。傾斜2°でも1セル進むと層座標が約929.7m変わるため、薄い層を粗い格子で拾って岩種が頻繁に切り替わる。これは空間的な標本化不足になる。

実際に保存済みのSeed12345で、同じ地質区分に属する陸地の隣接111,226組のうち80,710組（72.56%）で初期岩種IDが違っていた。この1Seedの観測を、すべてのSeedの統計とは扱わない。条件は使っているが、自然な分布としての作り込みは不足している。

今回の修正は表示に限定する。生成コード3本の内容をv30と比較し、全一致を確認した。分布を改良するときは、地質帯の連続性と格子に合う地層表現を設計し、既存rock-24-v1の保存を維持する新しい生成プロファイルで検証する必要がある。

## 表示修正

旧版は岩石番号の剰余計算で強い色を作り、各数値表示を同じ赤〜水色で表示していた。凡例は既存「情報・凡例・時間」の閉じたdetails内にあり、目盛りや安全率の意味も不足していた。

- 岩石は明示した24色の落ち着いた配色。凡例で火成岩8・堆積岩9・変成岩など7に分類し、各色へ岩石名を表示。
- 侵食耐性は薄いベージュ〜濃い茶。0.2 / 0.5 / 1 / 2 / 4の対数目盛り、相対値・単位なし・高い値の意味を記載。
- 透水性は薄い砂色〜落ち着いた青。10⁻²³〜10⁻¹¹ m²の目盛りと、水の通りやすさを説明。
- 安全率は1未満 / 1〜1.5未満 / 1.5以上の3区分。生成時モデルの地域値であり、キャラクターが歩ける坂の判定とは異なることを記載。
- 表示選択時に左側の専用「色の説明」を開く。閉じる/再表示可能。UI非表示で隠れ、スティックとアクション操作を残す。
- 海・湖・河川の元の水域色を保ち、岩石や数値の色を重ねない。既存テクスチャのalphaへ表示専用マスクを格納し、新しい全域配列やサンプラーを増やさない。
- 表示色と凡例は `rock-display.mjs` へ共通化。GPUの色テクスチャも同じ定義から作り、数字の意味と実際の画面色を照合。

既存の情報detailsだけを自動で開く案では小さいメニューの下へ凡例が隠れるため、左側の独立したスクロールパネルを採用した。分布の滑らかさをごまかす色補間は行っていない。

## 検証

実画面確認で不透明なスクロールパネルの下へ黒抜けが出るChromium/WebGLの合成不具合も検出した。同じページの背景不透明度だけを切り替え、不透明では下側の画素がRGBA(0,0,0,0)、約98%では元の地図色になることを確認。視覚上ほぼ不透明な約98%の背景を使い、画面の読み戻しで枠外に透明な穴が出ないことを回帰検証する。

97件の単体テスト。WebGL1で24岩種IDと4モード×24地点の色を読み戻し、凡例の色と一致することを確認。既存マテリアルの4つのテクスチャ参照も残してコンパイルした。

実ブラウザでは同じ通常世界を使い、横667×375 / 844×390 / 1180×820で凡例の自動表示・名前24種・数値/単位/意味・再表示・UI非表示・既存操作UIとの重なり・俯瞰切り替えを確認する。結果は `validation/v31/browser.json`。iPhone/iPadのSafari実機は検証していない。

v30のA〜D実験・通常3Seedの数値は生成コードが同一のため再実行していない。v30報告内の比較画像は当時の配色の記録であり、v31の識別色とは異なる。
