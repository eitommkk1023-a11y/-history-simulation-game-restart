# World of History — 馬の試作02

本作への統合前に、造形・乗降・歩法・大量表示を試す独立HTMLです。元のワールド、セーブDB、mainは変更しません。

## 実行・再生成

Node.js 24、ブラウザテストには Playwright と Chromium が必要です。依存ライブラリは既存の `exports/World-of-History-development.html` 内の固定 Three r128 をSHA256で照合して再利用します。ビルド時・実行時のCDN取得はありません。

```sh
node tools/build-horse-assets.mjs
node tools/export-horse-glb.mjs
node tools/build-horse-prototype.mjs
node --test --test-isolation=none --test-reporter=spec tests/*.test.mjs
node tests/horse.browser.cjs
node tests/horse-visual.browser.cjs
node tests/horse-input.browser.cjs
```

開くファイル: `exports/World-of-History-horse-prototype-v2.html`。
ブラウザ試験はローカルHTMLをPlaywrightのHTTPルートから返す方式です。`/usr/bin/chromium` を使用します。

## 操作

- 横画面。左スティックで移動、右の画面をドラッグしてカメラ操作。
- 馬の近くで「乗る」。乗馬中の「降りる」は減速して停止後、安全な横へ降ります。
- 「常歩／速歩」で基本速度、「駈歩」で走行を切り替えます。駈歩中はボタンが光り、再押下・移動入力停止で解除します。
- 「全体を見る」では馬の操作を停止します。「UIを隠す」でもスティックとアクションは残ります。
- 「試験設定」で1・100・1000・5000・10000頭、整列／行進、別個体を選べます。
- PC: WASD、マウスドラッグ、E乗降、Shift駈歩、V視点。

## 構成と計測範囲

`identity.mjs` が個体ID・Seedから毛色、白斑、体格、最高速、加速、持久力、旋回を決定します。外見と能力は別の乱数チャネルです。選択した個体IDだけを `woh:prototype:horse:v1` に記録し、再読込で同じ馬に戻ります。

`motion.mjs` の20骨格と常歩（4節）、速歩（対角肢）、駈歩（左右非対称）の接地・遊脚からポーズを生成します。操作する馬はCPUで地面の足位置を解き、GPUへ20本の行列を送ります。集団は4クリップ×48フレームの共通骨格テクスチャを利用し、個体別の時刻・歩速・色で描画します。r128のSkinnedMeshをそのままインスタンス化する方式ではありません。

`model.mjs` は馬体、首、長い頭、耳、たてがみ、尾、四肢、蹄、鞍を持つ独自の簡略モデルです。近2132・中1064・遠174三角形。集団は最大3描画バッチ、操作馬は別の1バッチ。全体カメラの5000頭試験では操作馬＋遠景4999頭の2バッチになります。全シーンの描画回数には地面、岩、1人の騎手なども含まれます。

CPUの画面外判定・LOD振り分けは10Hz。画面に近づくと詳細化し、境界には距離の余裕を設けています。完全なLOD形状補間は未実装で、近寄れば切替を認識できる場合があります。

集団は円弧に沿って行進する**描画用の負荷**です。5000頭の衝突、経路探索、独立思考、5000人の騎手・装備・戦闘は実装していません。馬同士の衝突も対象外です。操作馬は固定岩、地面の段差・勾配、試験場の端を判定します。高速時も小区間に分け、急斜面へ進入しないようにします。

地面の描画と高さ問い合わせは同じ三角形補間を使用します。これは元の地理生成器との接続試験ではなく、馬を測るための専用試験場です。

## 資産と出力方法の変更

GLBは同じ頂点・骨格・ポーズから直接出力し、3つの独立LODシーンと4アニメーションクリップを格納します。骨格位置をランタイムと読み戻し比較しています。

Blender 4.3.2ではメッシュ構築後の評価・保存が停止／異常終了したため、Blender経由の書き出しを採用しませんでした。編集可能な元データはモデル生成のJSです。`game-dev` CLIはこの環境に存在しないため、同CLIの検証済みパッケージとは扱っていません。外部のglTF Validatorによる認証も未実施です。独自構造検証・骨格読み戻し・実際のGPU描画比較を実施しました。

外部のモデル、テクスチャ、課金サービスは使用していません。独自資産の権利は本プロジェクト用として記録し、再配布ライセンスを勝手にCC0等へ変更しません。組み込みThree.jsのMIT表示を保持しています。

## 検証結果と残る確認

試作01の初回検証では106件の単体テストと23項目のブラウザ検証が通過。GPUで変形した馬とCPU基準モデルは、停止・常歩・速歩・駈歩それぞれの固定ポーズで256×256のシルエット差分0画素でした。全フレーム・全機種の一致を保証する試験ではありません。

乗降、塞がった場所の降車拒否、加減速、旋回制限、緩い坂・急斜面、地面の一致、複数指の独立入力、UI非表示時の操作維持、個体再読込、667×375・844×390・1180×820での配置、頭数・描画数・画面外除外を確認しました。実際の画像は `validation/horse/` に保存します。

**iPhone/iPadの実機速度は未計測です。** ChromiumのSwiftShaderはCPUによるソフトウェア描画で、5000頭は約0.9FPS、10000頭は約0.4FPSでした。表示できることと、スマホで軽快に遊べることは別の確認です。スマホの快適性は達成済みと扱いません。最初は1頭、その後100→1000→5000と増やし、実機のFPSと発熱を確認する必要があります。

計測の生データは `validation/horse/browser.json`。FPSは1.5秒の準備後、約5秒以上のwall-clockサンプルです。三角形数・馬のバッチ数は馬のみ、`totalRender`は全シーン。JSヒープはブラウザの概算、`bufferEstimateBytes` は確保した一部のGPU用配列の合計であり、端末の総消費メモリではありません。

歩法・造形・騎乗姿勢はまだ試作です。実馬のモーションキャプチャは使用せず、手続き的な簡略動作です。歩法の切替は0.16秒で混ぜており、切替中・急旋回中の厳密な足固定は対象外です。

参考資料: [Horse movement](https://horses.extension.org/horse-movement-and-way-of-going/)、[Canter](https://horses.extension.org/horse-canter/)、[USDF gait overview](https://www.usdf.org/EduDocs/The-Horse/HowManyGaitsAreThere_2007_Jan.pdf)、[British Dressage paces](https://www.britishdressage.co.uk/our-sport/all-about-dressage/paces-and-movements/basic-paces-walk-trot-and-canter/)。足順の設計参考に用い、モデル・画像は転載していません。

## 試作02の修正
カメラを基準にした左右方向が反転していたため、入力から進行方位への変換の符号を修正しました。徒歩・騎乗、カメラ4方位、スティック・WASD、前後左右64ケースと、ブラウザへのタッチ入力4ケースで実際の移動先を確認しました。関連単体テスト7件も通過しています。iPadで軽快だったとのユーザー報告はありますが、機種・FPSは未計測、iPhone 17も実機未確認です。初回のソフトウェア描画の測定を実機速度へ換算しません。
